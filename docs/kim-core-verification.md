# KIM 内嵌核心专项核验

日期：2026-10-30。依据用户要求，重新检查是否实际嵌入、自动参与、可以执行，并区分原生实现与外部 Skill。

## 结论

**内置治理核心能运行，并已通过真实模型的规划与多窗口执行检查；它不依赖用户目录里旧的 meta-theory Skill 才能启动。** 正常外部 Skills 仍可使用。

准确范围是：Emergence 把 Meta_Kim 的角色职责、流程契约和治理方法转为自己的原生模块，通过 Harness 事件、工具注册、执行门禁与 Collaboration 调度运行。不是把整个上游运行库原封不动嵌入，也不能把全部上游角色、算法或可选服务都标为完成。出处、未接入项继续见 [能力台账](meta-kim-capability-map.md)。

## 实际接入位置

| 部件 | 运行方式 |
| --- | --- |
| 固定来源与角色/流程目录 | `src/core/assets/catalog.ts` 随应用构建；加载时验证摘要与 schema，形成不可变目录 |
| 任务入口与目标分析 | `CorePlanning.mount()` 监听 Harness 接纳的真实请求；原生 `emergence_analyze` 记录语义目标，`emergence_plan` 提交有验收条件的计划 |
| 执行约束 | SessionController 的审批与最终工具执行两处复查规划门禁；角色和 Skill 文本不能替代权限 |
| 规划落地 | `emergence_execute_plan` 接现有 Collaboration、SQLite 台账与执行窗口，实际结果由工具/任务回执驱动 |
| 审查与验证 | CoreAssurance 创建独立上下文，检查真实读取/命令回执及产物版本；文字宣称不等于通过 |
| 经验与记忆 | CoreMemory / MemoryStore 管理作用域、候选、用户批准、纠错、遗忘和恢复后召回 |
| 外部 Skills | 原有 Skill 服务提供任务专用方法；内置核心可以选用它们，但核心不以加载某个外部 SKILL.md 为启动条件 |

## 本轮发现与修复

新增反例“把欢迎语换成中文”：原关键词初筛把它分到 direct，模型直接 write 时竟能跳过目标分析。测试先复现一次实际写入，再修复为：即使初筛没识别出实施意图，写文件、编辑、Shell、子代理派发及 MCP 等已识别副作用也必须先通过原生分析门禁。模型不能靠不同措辞绕过它。

主窗口在语义分析后把任务升级为 focused 时，如果存在可派工窗口，会进一步转为 planned，仍需计划检查。已有主控契约的执行窗口、受运行时所有权管理的子代理继承已批准的任务入口，不启动竞争分析；Plan 的副作用拒绝继续由权限层直接执行。安全回归核对了原有审批、目录规则、子代理归属及继承权限。

测试模型夹具补上正常的目标分析步骤，原来的权限拒绝、规则变更及命令失败断言保留，没有通过关闭核心来回避回归检查。

## 测试证据

统一记录：`artifacts/kim-core/inspection.json`。

1. **116/116 全量单元与 Harness 集成测试通过。** 包括无关键词任务的门禁反例、模型分析升级、派工、恢复、权限、证据和记忆。
2. **真实 DeepSeek 多窗口执行通过。** 在临时项目、独立 home 中，通过实际 CLI / Windows ConPTY 启动主控及执行窗口，发送普通文件修改任务。实际调用了分析、能力查询、结构化计划、执行图提交等原生工具；worker 改写并读回 `notes.txt`，任务返回 `needs_review`，无 worker 执行错误。耗时约 23.6 秒，详情 `live-team.json`。`needs_review` 不是完整验收通过；此测试在真实实施回执处结束。
3. **隔离外部 Skill 的验证通过。** 仅在上述临时 home 的测试配置中拒绝 `skill` 调用，实际 Skill 加载次数为 0。完整本地闭环还明确断言没有注册 Skill 加载工具，仍跑通“规划 → 实施 → 独立审查发现问题 → 一次修复 → 验证 → 经验候选 → 用户批准 → 重启后复用”。该完整闭环的模型是确定性夹具，Harness、文件与子进程真实运行，详见 `lifecycle.json`。
4. **正常 Skills 共存通过。** 在另一个允许 Skills 的测试配置下，实际完成内置分析、文件写读改、PowerShell、Skill 正文加载、本地 MCP 调用及恢复；OpenAI / Anthropic 采用本地协议服务。详见 `skills-e2e.json`。
5. **故障回归通过。** 限流、服务错误、断流不盲目重试；已发生的文件副作用恢复后不重放，实际杀进程后的连接释放与恢复通过。详见 `faults.json`。

真实配置只读核对结果：`core.mode=observe`、规划开启、没有拒绝外部 `skill` 工具。没有修改用户真实配置、删除 Skill 或更改其他应用的安装。
