# 主窗口自主编排：第二阶段交付

日期：2026-10-30。交付范围：自动拆解入口、窗口匹配、实际派工及有边界的并行；第三阶段的完整跟进/审查/修复/收尾仍待实施。

## 行为

设置主窗口后，用户只需提交总目标。主控先用原生需求分析区分实施、讨论和澄清，再读取项目来源，提交子任务、依赖、角色、实际路径范围、必需能力与验收标准。新的 `emergence_plan_work` 不要求模型填写窗口、会话或模型 ID，这些由宿主依据当前团队绑定。

匹配先过滤项目、可排队状态、工具、模型配置、角色所需模型/Skills 和权限限制，再按角色偏好、当前负载和实际成功回执排序。每项保存分配原因。没有合适窗口时明确说明缺口，不擅自切换目录或凭模型品牌猜能力。

宿主监听 Harness 的 `agent/turn-stopping`：有效实施方案尚未派发时自动进入既有执行队列；模型只说“我来安排”但没有有效决定时，最多在原轮次纠正两次。另有 24 个规划模型步骤上限和步骤边界的 180 秒时长检查。校验失败、预算耗尽或拒绝审批会留下中文阻塞原因。普通直接问答可用结构化 answer 决定，不强行拆任务。原有记忆、审查等主控治理操作保留。

## 执行与权限

- 自动派工继续经过计划校验、当前角色/窗口绑定、用户权限与审批，使用原有 Collaboration 和 SQLite 台账。Plan 模式可准备分工但不会执行；讨论和关键问题未解决时也不会实施。
- 任务图含请求准入标识，同一图重复提交不创建重复任务。主控协调模式的实施步骤交给执行窗口，不靠主控直接写文件绕过分工。
- 自动匹配的文件任务使用具体路径范围。其实际 read/read_image/write/edit 必须留在范围内，范围外文件、Shell、全项目检索、子代理和外部工具均会被拒绝。需要更大能力的任务须在方案中声明，并使用保守的独占调度。
- 物理路径（含 junction 解析）不重叠的受限任务可以并行；路径交叉、父子目录、范围未知或独占任务保守串行。同一执行窗口仍按队列逐项执行；有逻辑依赖的步骤仍等待上游实际验收，不把 worker 自述当作成功。
- 角色偏好不增加权限。最终执行仍继承主控、worker 和角色权限。自动执行路径也检查绑定后的计划长度，避免绕开原工具路径的上下文预算。

## 主要文件

- `src/core/adapters/planning.ts`：原生主控决定、工作分解、结束检查与预算。
- `src/core/application/work-allocation.ts`：真实候选过滤和分配理由。
- `src/core/application/task-allocation.ts`：物理路径冲突与受限文件任务门禁。
- `src/app/collaboration.ts`：复用队列的有界并行、任务约束和取消信号。
- `src/app/team-coordinator.ts`：分配明细和阻塞状态；`/team` 可查看。

## 使用

重启 `emergence`，打开两个或更多窗口，右键设置主窗口，然后向主窗口给出总任务。需要时查看 `/team` 的分配原因或 `/tasks` 的实际状态。角色偏好默认自动即可。

本阶段没有修改模型配置小窗口的界面或启动尺寸；用户已说明该请求交给另一个页面处理。
