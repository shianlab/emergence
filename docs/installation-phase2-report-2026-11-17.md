# 安装改进第二阶段：统一维护事务

本轮范围：安装、更新、同版本修复、回退、中断恢复及旧版本清理。仅构建本地候选；不发布 GitHub、不修改实际用户安装，不恢复多窗口协同。版本仍沿用 1.0.1 作为测试候选，不能把候选行为当成当前已发布 1.01 的行为。

结论：第二阶段完成。最终源码检查、368 项单元回归及真实维护 9 项、旧版迁移 5 项、完整发行包 14 项均通过；未发现阻塞本阶段验收的问题。

## 实现与职责

旧 `manage.cjs` 的安装实现已迁出，文件只保留命令适配及既有测试所需的兼容导出。`installation/` 按 service、transaction、files、windows、retention、diagnostics 分工；在线安装、完整发行包安装和 CLI 维护使用同一服务。详细归属和资源生命周期见[维护边界](structure/installation-maintenance.md)。

- 候选先完整部署和实际启动探测，再准备入口与 PATH、切换指针并复核启动。持久事务保存入口、指针和 PATH 快照。未提交中断恢复旧状态，提交后中断保留新版本并完成收尾。
- 版本号与物理目录分离。同版本修复写入新目录，正在运行的旧实例继续使用原文件。管理器有独立指针，回退旧产品仍可运行新版维护引擎。
- CLI 与原生模型配置程序持有系统文件句柄；旧版清理结合进程查询、安装身份、清单、链接和额外文件检查。PID 记录仅供诊断，不作为删除依据。
- PATH 使用快照与并发修改检查，保存原注册表类型。`-NoPath` 安装偏好随维护保留。自定义入口不被静默覆盖。
- 安装诊断保留分段计时和失败阶段，不写凭据、模型请求或用户配置正文。诊断写失败不能把已完成的安装改报为失败。
- 新命令为 `update --source`、`repair --source`、`rollback`、`installation status|cleanup|recover`；源码与便携入口明确拒绝受管维护。自动联网检查和 TUI 提醒属于第三阶段。

## 巡检修正

1. 隐藏维护进程的输出显式转发，避免嵌套 CLI 调用收到空结果；中文使用 UTF-8，进度逐行显示。自动恢复静默执行，`--version` 不混入恢复 JSON。
2. 占用查询排除执行维护脚本的 PowerShell 控制进程；查询超时或无法判定时延后清理。保留真实 CLI/Node 和原生工具占用检查。
3. 清理等待并发文件操作完成、检查所有权与未知文件；清理错误与新版本启用结果分离。
4. 更新按语义版本顺序处理预发布标识，不能把正式版更新到同版本号的较早预发布版本。
5. 自有 CJS/JS 文件进入现有格式检查；模块没有引入新的运行依赖、第二套用户配置存储或 Agent 执行循环。

## 边界与后续

- 本机受测场景通过不等于所有其他电脑已验证。对方此前“装好仍需修复”的具体操作无法取得，不能宣称已复现该未知问题。干净机器、弱网和正式分发属于第四阶段。
- 旧式启动器没有版本使用句柄协议，自动清理保留这类目录；未知内容或占用不明也保留，安全优先于强制回收空间。
- 程序回退不回滚用户数据；数据协议不兼容则拒绝。首次安装入口未建立、旧启动器迁移未完成或入口本身损坏时，使用完整发行包重跑安装。
- 下一阶段接入可信版本清单、后台检查、中文更新提示与在线更新入口；复用本阶段事务，不另造更新脚本。
