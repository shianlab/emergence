## 已交付

- 工作台模板：保存多项目、多模型布局及主控/执行者角色，支持 `/template` 和 `emergence --template`。载入使用新会话，保留历史并备份原草稿；目录或模型出错时保留原窗口。
- 个性化：dark/amber/light 主题、自定义颜色、快捷键冲突校验、状态栏字段及中英工作台控件，集中持久化，立即生效。
- Harness 能力入口：Skill 发现/查看/显式调用、MCP 启停和失败隔离、工具权限、上下文查看/补充/导出、活动及已结束子代理查看。新增配置兼容旧 config.json。
- 模型档案：展示协议、预算、密钥配置状态及能力声明；切换保留历史，对明确不兼容的工具/图像历史拒绝切换。
- 本地扩展：显式 ESM 模块加载，命令/面板/工具入口，初始化失败回滚、协作式取消与资源清理。内置 inspector 和外部 project-notes 示例均已实际验证。

## 实现与巡检中处理的问题

- 显式加载 Skill 使用 Harness 规范的 skill-invocation 和 renderSkillContent，保留资源基路径，保证相对资源引用可解释。
- 为 Cordis 插件显式声明 skills、subagents 依赖，修复实际 profile 中服务访问被拒绝的问题。
- 扩展在异步初始化期间停用时，等待晚到的清理函数并完成释放；抛错初始化不会留下已注册工具。后台命令完成不抢夺其他窗口焦点。
- 工具权限最终 guard 再次检查拒绝规则及所属窗口的单次确认，其他策略监听器不能绕过；规则变更要求执行空闲。
- 更新主题等显示配置时，不把其他实例的权限修改顺带应用到正在运行的会话。
- 子代理结束后从 Harness 持久目录查看记录，不要求其继续驻留，也不重新启动它。
- 保留原生子代理固定委派权限；需要额外审批的操作按 Harness 策略自动拒绝，未改为自动授权。

## 使用与后续边界

重新启动 `emergence` 即可使用。常用入口：`/settings`、`/template`、`/capabilities`、`/extensions enable inspector`。完整说明见[个性化使用指南](personalization.md)，逐项覆盖与缺口见[能力对照](capabilities.md)。

扩展是受信任的进程内代码，需正确登记资源和响应 AbortSignal；不隔离恶意代码或无限循环。中英设置覆盖工作台控件，模型内容和部分底层说明不强制翻译。MCP 为工作台共享进程；新增服务参数、模型路由、技能目录及扩展代码变更需重启。模型能力为配置声明，不代替实际供应商验收。

另一真实供应商、物理中文输入法、其他终端、长时间压力测试、干净环境安装与升级属于第六阶段。ConPTY 测试驱动在确认应用及 shell 退出后显式结束，以处理 node-pty 保留的 conout worker；本报告不据短时测试宣称所有内存自然回收或长期性能已验收。
