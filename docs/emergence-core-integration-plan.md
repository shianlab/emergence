日期：2026-10-30。最初规划时仅阅读源码、压缩包和官方交互文档，未安装 Meta_Kim、执行其脚本或修改应用运行代码。

实施进度更新（2026-10-30）：第一至第六阶段已按后续授权实施；第六阶段 16 组检查、112 项测试及五分钟稳定性通过，进入本机试用。完成内容、真实服务验证和未覆盖范围见 [第六阶段报告](core-integration-phase6-report.md)。完成的是本方案所述 Emergence 原生核心及验收，不表示上游全部源码与未配置外部服务已迁移认证；无整合前构建基线，性能采用同构建 off/observe 对照。下文“本轮”保留为最初规划时的研究记录。

## 目标与当前判断

Emergence 继续作为独立应用：运行 `emergence` 即可使用。Meta_Kim 的任务治理方法、角色职责、契约和可复用运行逻辑成为内置核心能力，正常任务自动使用，用户不需要安装或手动调用 meta-theory Skill。DeepSeek Harness 继续承担模型与工具执行底座，多模型、多项目、多窗口保持可用。

本次同时解决三件事：输入 `/` 就能获得中文指引；任务执行有真实、清楚、具有“涌现”个性的状态；复杂任务具有从理解目标到执行、审查、验证、经验沉淀的完整闭环。

### 已核对的现状

- `emergence/src/app/tui/commands.ts` 已有中英文命令定义与筛选；`command-list.ts` 已有选择列表。应扩展和统一入口。
- `tui/home.ts` 当前只处理若干提交后的命令和模型/历史菜单，未接入与对话页一致的斜杠推荐。首页未知斜杠命令还可能进入普通任务路径，应在第一阶段拦截并引导。
- `workspace.ts` 的帮助包含大量语法、ID、英文枚举；部分内容虽是中文，仍缺少任务导向的解释。
- `tui/composer.ts` 已区分运行、输出、工具、待回答、停止和错误，但通用“运行中”与灰色展示还不能提供用户要求的反馈。
- 已有权限模式、项目指引、角色任务、依赖、审查/修复、会话持久化等基础。整合需保留现有实现和已通过的安全回归。

## 核心整合结构

```text
Emergence 中文 TUI / 命令 / 状态 / 审批
                    │
Emergence 内置治理核心
目标与验收 → 证据与能力发现 → 规划与角色 → 审查与验证 → 经验沉淀
                    │
现有 Workspace / Collaboration / 权限系统
       一套任务图、一套调度、一套执行事实
                    │
Emergence Harness 适配 → DeepSeek Harness → 模型 / 工具 / MCP
                    │
版本化任务事件、检查点、产物证据、项目记忆
```

建议新增 `src/core/`，按 domain、application、adapters、storage 分层；现有界面通过稳定的命令与事件接口读取核心状态。具体文件划分在第二阶段确定。

三类内容分别承接：

1. 方法和角色材料转成内置、版本化策略资产，按当前任务和阶段选择加载；不把整包长文塞入每轮上下文。
2. 契约、状态迁移、校验和证据逻辑转成可执行模块和测试；通过代码保证权限、预算、验收条件。
3. 宿主 Hooks、CLI 适配和安装逻辑转换为 Emergence 生命周期接口；不依赖用户安装 Claude Code/Codex，也不复制它们的全局配置。

“完整吸收”以逐项能力台账验收：每项均有来源、成熟度、目标模块、改造方式、依赖、测试和落地状态。核心能力全部纳入路线；宿主专属设施做等价适配，外部服务保留内置连接能力并显式呈现缺失条件，历史或不适用资产注明原因，不能用“复制了文件”冒充集成完成。

## 六个实施阶段

### 第一阶段：中文命令引导与真实状态

交付：直接改善日常使用，覆盖用户的第一、第三项诉求。

- 首页和对话页输入 `/` 立即出现可用命令，无需先按回车；常用项优先，支持英文命令和中文用途搜索。
- 命令列表展示中文名称、一句话用途、当前实际快捷键；模型、权限、窗口和任务优先提供选择器。
- ↑↓ 选择、Tab 补全、Esc 收起并保留草稿。Enter 对完整可执行项进入对应动作；需要参数时进入参数选择/填写，不提交空参数。危险动作仍经过现有审批。
- 重构 `/help`，按“开始对话、模型与权限、窗口与协作、能力与记忆、故障帮助”分类，提供中文说明和可直接使用的例子；首页仅呈现当时可用的操作。
- `/帮助` 可作为 `/help` 别名；纯输入 `help`/“帮助”可打开帮助，普通句子中的这些词不被拦截。英文命令保留兼容，内部术语不直接充当交互文案。
- 命令注册表统一驱动菜单、帮助和参数提示，避免入口各维护一份。IME 输入组合、粘贴、多行文本、路径中的 `/` 不误触发执行。
- 每个窗口独立状态：连接模型、等待响应、收到推理事件、输出回复、调用工具、等待审批、排队、停止、失败。状态绑定 pane/session/run，旧任务事件不污染新任务。
- 输入框上方预留一行，例如 `◌ 正在涌现… · 等待模型响应 · 8 秒`、`◌ 涌现正在翻文件 · 读取 README.md`、`◇ 轮到你啦 · 等待操作确认`。编排阶段接入后扩展为“正在拆解任务”“正在复核结果”。
- 未收到实际推理事件时只显示“等待模型响应”，不编造内部思考或百分比；长时间无事件明确显示等待时长和取消入口，不擅自认定连接已断。
- 按本次新要求，仅状态文字/图标采用单一柔和强调色，建议低饱和琥珀；背景、Logo、正文继续黑白灰。提供灰阶/减少动效配置，颜色之外始终有文字和符号。

验收：Windows 真实终端中，首页及对话页的斜杠菜单、中文过滤、帮助、参数填写、审批、取消、中文输入、窄屏和多窗口均可操作；真实流式/工具/失败事件与状态对应。此阶段新增检查不改写另一个 UI 页面的既有视觉成果。

### 第二阶段：完整能力映射与核心接入基础

交付：可以装载、校验、观察的 Emergence 内置核心，以及完整迁移台账。

- 清点 Meta_Kim 的方法、九个治理角色、工作流、契约、能力目录、记忆、进化、持久化、Live 投影和依赖。区分实现、shadow、fixture 与尚未证明的运行能力。
- 映射关键职责：Conductor 编排、Scout 能力发现、Artisan 能力组合、Genesis 角色设计、Prism 审查、Warden 质量裁决、Sentinel 安全、Librarian 记忆、Chrysalis 经验沉淀；对外采用中文名称，内部保留来源追踪。
- 保留八阶段核心循环与十一阶段业务工作流的对应关系，不误合并成一套含义模糊的阶段列表；用户界面仅显示当前相关进度。
- 建立类型化输入输出、策略版本、事件接口、存储 schema 和 Harness 适配端口。默认启用内置核心，先以观察模式比较新旧判断，避免直接替换现有调度。
- 明确指令层次：内置身份/规则、用户配置、项目 `EMERGENCE.md`、任务上下文和检索资料。项目文档与检索内容不直接授予执行权限；模型建议不能绕过代码中的权限检查。
- 为源码改造记录来源、变更和包内 LICENSE/NOTICE，纳入第三方声明；逐项检查额外依赖的来源和版本兼容。不上游安装器、不修改其他 Agent 的全局配置。

验收：能力台账无无解释遗漏；缺失资产/契约错误可诊断；关闭实验接入仍可运行原有流程；无需单独安装 Skill 即可装载核心。

### 第三阶段：意图理解、能力发现与任务规划

交付：普通自然语言请求自动进入合适工作流。

- 把目标、约束、验收标准、非目标和关键未知项形成结构化任务描述。只对会改变结果、权限或路线的缺项提问。
- 轻量问题走简短路径，复杂任务按需规划；不让每个问答都启动九个角色或跑完整十一阶段。
- 统一登记实际可用的模型、原生工具、MCP、用户 Skills、内置方法和角色。区分“已登记”“已连接”“可调用”“已验证”，缺少服务不能假装有能力。
- 基于任务要求选择能力、执行窗口、模型与上下文，形成带依赖、边界和验收条件的计划。单窗口独立与主控派工模式均可使用。
- 研究发现、候选路线、冲突证据和选择理由按需展示；读取文件和外部证据后再制定依赖这些事实的计划。
- 设置上下文和研究预算，压缩时保留目标、授权范围、未完成任务与证据引用；临时材料不自动晋升为长期规则。

验收：用简单问答、明确修复、模糊需求、多项目任务和能力缺失案例检查路线；实际工具绑定可追踪；轻量请求不受复杂流程拖累。

### 第四阶段：可靠执行、调度与中断恢复

交付：规划在现有 Harness 中真实执行，并能准确报告和恢复。

- 扩展现有 Collaboration 任务图，承接治理阶段和工作任务；统一任务、会话、模型、项目、尝试次数和证据标识。
- 通过 Harness 实际事件驱动工具/模型执行状态，保留现有审批、取消、角色约束和有限修复；不会创建第二个竞争调度器。
- 治理职责按需调用，实施职责交给对应 worker。多项目可并行；同项目写入冲突串行协调或使用隔离工作树；发现外部修改后重新验证产物。
- 先建立耐久事件和事务存储，再接入检查点恢复；旧会话与旧任务采用版本化迁移，备份并支持回退。
- 用 lease/fence 或等价机制防止重复主控、过期 worker 更新和重复派工。中断后区分“尚未执行”“已完成”“结果不确定”。
- 对可能已经发生的写文件、Shell 和外部调用先核对事实；未知结果进入待核对状态，不自动重复副作用。不承诺任意外部工具 exactly-once。
- 设置并发、步数、超时和修复次数上限；真实不可用的 token/费用信息显示未知，不用估值冒充账单。

验收：同/不同项目、同/不同模型、依赖失败、取消、审批中断、窗口关闭、进程重启、旧 worker 回写和未知副作用均有故障注入证据；权限不随重试或恢复扩大。

### 第五阶段：审查验证、记忆与经验沉淀

交付：任务结果有证据，经验可复用且可撤回。

- 区分“执行结束”“审查通过”“验证通过”“用户验收”。审查结果绑定当前产物版本/摘要、具体验收项和来源；改动后旧证据失效。
- 按复杂度分配独立审查和验证上下文；角色名不同不等于独立证据，测试失败或没运行必须如实记录。
- 审查发现问题生成有边界的修复任务，保留原权限、任务范围与版本；超过预算停止并说明。保留元审查与反馈机制，避免无限互相审查。
- 建立会话、项目、个人三级记忆；项目默认隔离，个人偏好显式共享。提供查看、检索、纠错、遗忘、版本和来源追溯。
- 接入 Librarian/Chrysalis 方法，形成“经验候选 → 证据检查 → 策略/用户批准 → 写入 → 可回滚”的生命周期。模型角色批准不能替代真实用户授权或权限系统。
- 通用偏好、项目事实与可执行策略分开保存；高影响的角色、工具或规则变更必须预览具体差异，不能由模型悄悄改自身权限。
- 将记忆服务、Graphify 等依赖能力纳入台账与连接适配；核心本地记忆必须能独立运行。未配置外部依赖时显示降级范围，不能标注整套外部能力已验证。
- 内置任务详情呈现对应的运行图/任务列表、证据和历史回放；先复用当前 TUI，不强制引入上游独立 Web 控制室。

验收：伪造完成、过期证据、失败测试、无证据审批、跨项目串记忆、敏感数据写入、撤回后再召回、反馈无限循环均被阻止或准确标记；用户能看到实际保存的经验内容。

### 第六阶段：整体验收与本机试用

交付：可在本机反复调试的版本、巡检报告和已知限制。

- 联通“输入任务 → 规划 → 真实工具执行 → 审批 → 审查 → 修复 → 验证 → 记忆 → 再次任务复用”。
- 覆盖终端交互、中文文案、快捷键、颜色降级、窗口切换及状态一致性；执行错误、断网、限流、MCP 超时、上下文压缩和重启恢复。
- 已配置模型做小规模真实 API 验收；其他协议采用本地受控服务并标注覆盖层级。MCP 分别报告本地真实进程测试和已配置外部服务测试。
- 比较整合前后轻量任务延迟、复杂任务成功率、修复次数、上下文用量和内存。测试通过之外，还检查是否产生不必要的流程负担。
- 核对逐项能力台账，清楚列出已完成、外部依赖未配置、上游尚无实现证据、不适用宿主设施。保留测试命令和产物引用。
- 在可回退配置下进行本机试用；本轮不以安装包或 GitHub 发布为交付条件。

验收：关键链路无阻断问题；不把模拟验证等同真实服务验证；任何未落地或未验证能力明确列出。

## 实施与协作约定

- 第一阶段完成后即可交付试用；第二至五阶段分别交付核心能力，不等到最后才看效果。
- 每阶段结束主动巡检并报告：完成内容、修复问题、测试证据、未验证项、下一阶段入口。
- 涉及 `workspace-ui.ts`、`tui/home.ts`、命令注册和状态组件时，保留另一 UI 页面的最新改动，以最新代码和同版本测试为准。规划阶段不改动共享界面。
- 用户批准开始某阶段后再进入该阶段实施；本文件中的命令或模块名称属于设计提案，未实现项不作为当前功能宣传。
