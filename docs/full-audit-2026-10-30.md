## 修复内容

| 问题 | 修复与验证 |
| --- | --- |
| 配置服务在读完请求体之后才计入并发操作，慢请求能够绕过忙碌判断 | 在读取请求体之前占用操作名额，所有成功、错误路径统一释放；真实 HTTP 回归验证第二个请求得到 409，错误请求不影响后续保存。 |
| 未发送完整 JSON 的客户端可能拖住配置服务关闭 | 跟踪正在读入的请求，关闭时取消读入、停止接收连接并等待已接纳操作结束；回归要求关闭在 1.5 秒内完成。 |
| 原生窗口尚未启动完成时关闭服务，可能晚到一个失去管理的窗口 | 使用独立的 ConfigurationWindowManager 统一管理启动合并、已有窗口聚焦、等待和关闭；验证启动中关闭、聚焦中关闭、重复打开、关闭后拒绝重开。 |
| 原生高级参数限制为 1000 万，保存又转成 32 位整数，与后端合法配置范围不一致 | 输入范围与后端正安全整数一致，保存采用 64 位整数。真实窗口展开并保存上下文 9007199254740991、最大输出 2147483648，文件逐字不变。另释放读取 DPI 时创建的 Graphics 资源。 |

产品修改集中在 `emergence/src/app/model-config.ts`、`model-config-window.ts` 和 `emergence/native/model-config/Program.cs`。没有增加另一套调度器或权限入口，没有改动已定稿的 TUI 布局。
