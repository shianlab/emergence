# 主控自主编排第三阶段：自动跟进、审查与收尾

日期：2026-10-30。此阶段属于主控编排，不是视觉改版阶段。继续使用现有 TUI、KIM 原生规划与 Collaboration 调度器。

## 实际行为

用户设置主窗口并提交自然目标后，第二阶段生成的执行图现在会继续自动推进：实施结果 → 独立验证 → 独立审查 → 接受结果 → 释放后续依赖 → 最终汇总。存在有证据的缺陷时，按原契约创建有限修复，并对修复后的版本重新验证和审查。用户不用再输入“派审查”“继续检查”“验收这个任务”。命令执行仍遵循原权限审批。

自动流程属于宿主代码，运行在既有调度器的单一 pump 内；没有新增执行队列，不依赖模型记得逐个调用 audit/review/repair，也不依赖外部 Skill 被加载。审查、验证、修复仍使用已有的任务、角色权限、SQLite 日志和真实工具回执。

## 状态与证据

- 协调记录新增等待结果、审查、修复、等待用户、暂停、完成和取消状态，原有理解/规划/派发/受阻状态继续保留。
- 执行回执不逐条启动主控模型。宿主重读持久记录，合并重复事件；主控忙碌时保留事实，空闲后继续，无需用户提醒。
- 审查与验证使用不同会话，均不同于实施会话。同项目、同模型的空闲审查窗口可按职责复用，避免每次修复无限增加窗口。自动创建审查窗口不抢走当前焦点。
- 成功审查要求实际读取回执；实施类任务的整体验证必须引用实际执行、退出码为 0 的命令，但“读回内容正确”等具体文件项目可用读取证据，不能误要求每项都运行命令。只读研究/规划任务以另一会话的实际来源读取进行验证，不增加 Shell 权限。两者覆盖每条验收标准，模型说“通过”不能替代证据。
- 新增原生 `emergence_receipts`：返回当前检查任务自己的真实回执编号、文件 SHA256/字节数/末尾换行/BOM，以及同目标的有效独立验证结论。读取结果也附带该次调用的编号。模型不用从协议或历史消息猜测 ID。只读审查对运行类要求可结合已完成的独立验证，不要求它自己越权运行命令。
- `blocked:true` 区分“证据不足，无法判定”和“已观察到缺陷”，前者不会触发无意义修复。错误的证据元数据可以重新提交；正确提交后不再因已纠正的 `emergence_assess` / `emergence_report` 参数错误阻断验收，但原始拒绝仍保留在日志。报告先校验再入库，提前报告不会污染任务状态。实际读取失败、命令失败和非零退出码不被忽略。
- 文件读取按真实文件哈希核对版本；`glob` / `grep` 记录查询结果快照和查询根目录，不把目录误当作普通文件检查。查询快照本身不保证目录此后没有变化，实施产物与实际文件读取仍须通过版本核对。
- 验收时重算产物版本；提交最终汇总前重新核对最终文件。依赖步骤合法覆盖前一步产物时，以最新已验收步骤的文件版本为准。
- 汇总记录关联实施/修复/检查任务、实际文件摘要、验收项及回执 ID。Token 和费用仍显示未知，没有虚报计费。最终模型汇报最多 4 步；宿主汇总本身不依赖这段文字。

## 失败、安全与恢复

- 默认任务契约最多修复 1 次；配置契约上限仍为 3 次。每个总任务另限 12 次修复、96 次协调动作、1,200 个执行模型步骤及 30 分钟墙钟时间；暂停时间也计入墙钟预算。
- 只有已提交实际缺陷证据、已结束且副作用明确的实施结果可自动修复。工具失败、缺失报告、证据陈旧、命令未运行、权限拒绝、无可用审查空间或结果不确定，都不会被当作成功或盲目重跑。
- 修复继承原目录、会话、模型、角色、文件范围与权限上限；审查也继承原请求约束。Host 自动动作重新检查当前权限；要求确认时使用现有审批交互，拒绝后停止本总任务。
- 取消先持久标记总任务，再停止相关未结束任务；迟到回执不能复活取消任务。验收在异步文件核对后再次检查协调状态，防止取消与验收竞态。
- 重启仍回到独立/暂停模式。已结束但未审查的产物在用户重新启用协作后可继续审查，不重复实施。中断或副作用不确定的任务需先核对；旧总任务保留受阻状态。显式 `/recover` 经用户核对批准后可创建单独恢复尝试，不暗中重开已经结束的总任务；要继续新的自动任务图，可明确提交新目标。
- 模型不能为宿主管理的任务再创建竞争审查/修复流程；普通手动派工和原有治理工具继续可用。

## 本阶段边界

自动跟进覆盖本版本新接受的自主执行图，不把升级前的旧记录强行转成新工作。普通暂停停止新派发，已开始的调用按既有语义完成；要打断执行请使用停止/取消。复杂任务的模型拆解质量、检查命令选择和跨模型表现仍需要真实场景持续调试。第四阶段继续做可见协调反馈及更广的多目录、多模型验收，本阶段不做安装包或发布。
