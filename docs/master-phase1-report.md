# 主窗口自主编排：第一阶段交付

日期：2026-10-30。范围为主控职责、团队能力和总请求持久登记；不把第一阶段宣称为完整自动派工闭环。

## 已完成

1. 设置主窗口后具有明确的协调身份；默认角色偏好为自动。实时团队清单包含窗口、会话、目录、模型、角色偏好、当前任务和已锁定职责、权限、忙闲与用户接管状态。支持不同项目和模型，增删窗口后即时重算。
2. 将“可排队”与“可立即运行”分开：独立工作中和用户接管的窗口不能自动选用；已承担协作任务的窗口可排队，实际执行仍由既有调度器控制。
3. 按窗口列出注册工具、Skills、MCP 工具的候选可用性，以及当前请求已有的成功工具回执；MCP 服务状态单列。角色是声明或偏好，未根据供应商品牌虚构能力。权限/绑定在异步查询中变化时，丢弃该窗口旧能力并提示重查。
4. `emergence_team` 是接入真实 Harness 的只读查询工具；在 Plan 模式也不需要额外审批。主控模型上下文可获得团队信息；查询本身不创建或派发工作。
5. 新的主控工作请求经过 Harness 接纳后，在现有 SQLite 执行台账 metadata 中登记，关联原始消息 ID、请求摘要、需求理解、约束/验收、入口团队快照、计划和执行 ID。没有新调度器，也没有复用外部 Skill 充当入口。普通直接问答未进行任务分析时不创建总任务记录。
6. 同一消息重复登记保持同一 ID；计划澄清承接原记录，新目标单独登记。设置主控不回放历史，重启只恢复记录并保持协作暂停。记录保留上限和容量限制；存储失败会阻止对应模型步骤，避免假装登记成功。
7. 右键窗口可选择角色偏好、查看团队能力；支持鼠标、方向键/Tab 和回车，原有设主控菜单仍为首项。偏好改变仅供后续分工参考，不重写当前任务契约或权限。`/team`、`/window-role` 同时加入中文帮助和命令推荐。

## 使用与下一阶段

重启本机 `emergence`。右键设置主窗口后，可右键「查看团队能力」，或用 `/team` 查看中文概览。默认自动角色即可使用；可选「角色：偏开发/偏研究/偏审查」等。菜单中较后的项可用上下键访问。

恢复已有工作台时，保留主控身份和偏好，但协作仍暂停；需重新启用主控或协作。没有自动重放旧任务。

本阶段的总请求状态是入口/计划登记，最终执行状态仍以现有任务台账为准。稳定的自动拆解与匹配派发属于第二阶段；自动跟进、审查、有限修复和总任务完成判定属于第三阶段。
