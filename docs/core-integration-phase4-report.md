# 核心整合第四阶段：可靠执行与中断恢复

日期：2026-10-30。对应 `emergence-core-integration-plan.md` 第四阶段。继续使用 Collaboration 与 DeepSeek Harness；未安装 Meta_Kim Skill、未增加第二套调度器，没有修改首页、Logo 或对话视觉设计。

## 交付

- 通过检查的计划可由模型 `emergence_execute_plan` 或用户 `/plan run` 提交为持久任务图。步骤绑定窗口、会话、项目、模型、角色、依赖、范围、验收要求；重复提交去重，提交失败回滚整张新增图。单窗口步骤也进入同一调度器。跨窗实施步骤须分配给 worker，主控负责协调。
- 执行批次、租约版本、规划步骤、恢复次数进入任务详情。状态来自实际 Harness 事件；契约任务结束后仍须验收，依赖不能提前运行。同项目受管任务串行，不同项目按既有并发上限运行；独立人工操作不受这把任务锁控制。
- 新增内置 SQLite 事务台账，WAL + FULL 同步，保存最新任务状态、副作用记录和事件摘要。OS IPC 租约阻止第二持有者，数据库 epoch/owner 拒绝过期提交；旧子代理不能继续为结束的任务发起操作或把结果串到新任务。
- 副作用执行前先保存会话、派发意图和 started 记录，随后记录返回、失败或不确定。副作用表使用参数和回执摘要，不复制原始参数和输出；原有会话日志仍保存正常交互，这不是全部存储的脱敏承诺。
- 重启恢复事实但不自动重放。恢复限原派发会话，最多两次新尝试，继承原角色、权限、目标和范围，并叠加当前权限。窗口身份、权限或核对后文件变化会使旧确认失效。
- 原生恢复弹窗默认“暂不执行”：Enter 取消，方向键选择后 Enter 确认，Esc 取消。旧确认不能回答下一次请求。不确定副作用不能绕过核对自动修复或直接验收。
- 原生 write/edit 触及文件保存摘要，验收及后续依赖派发前重新比较；未知摘要不能作为一致证明。并发、模型步数、时长、有限修复沿用原预算，每任务最多 1000 个副作用调用。Token / 费用不可可靠统计时显示未知。

## 本机使用

关闭旧进程，在终端输入 `Emergence` 即使用更新的本机构建。

1. 正常描述复杂任务，模型可提交并执行计划。`/plan` 查看方案；窗口空闲时可手动 `/plan run`。
2. `/tasks` 查看实际状态；`/task accept <任务 ID> "实际核对证据"` 验收。执行结束与验收通过是两个状态。
3. `/recover` 查看中断任务，`/recover inspect <任务 ID>` 只读查看批次、调用记录、当前文件摘要、日志位置。
4. `/recover retry <任务 ID> "具体核对说明"` 请求新尝试，说明至少 8 字，在原派发窗口确认。跨窗恢复前先 `/mode collaborate`，已暂停时 `/dispatch resume`。
5. `/recover keep <任务 ID> "具体核对说明"` 保留已核对的不确定结果，只解除待核对标记，不重做、不自动验收；`/recover events` 查看最近事件。

确认框提示新尝试可能重复原副作用。Shell、外部服务和后台进程需要核实真实状态；文件摘要相同不能证明外部操作未发生。

## 存储与迁移

应用 home 下 `core/execution/<项目键摘要>.sqlite` 使用 schema 1。首次迁移先按原字节备份工作台 JSON 至相邻 `.legacy-<UUID>.json`，再导入。随后 SQLite 为任务权威，JSON 保留布局与兼容快照。布局缺失但台账有历史任务时明确报错，不悄悄清空。

`--fresh` 或显式新工作台先生成 `.archive-<UUID>.json` 归档旧任务图，历史会话与副作用记录保留。未知 schema、损坏台账、链接目录不自动覆盖。事件记录用于追溯摘要，不包含每版全部状态的完整回放。

回退前退出全部进程，备份整个 home（含数据库及可能存在的 WAL/SHM）；用迁移前 JSON 备份还原对应布局，搭配旧应用版本。旧代码不读取新台账；切回新版时恢复成套 home 备份，避免旧 JSON 与新 SQLite 混用。`/core off` 关闭规划和观察，不删除已有任务记录或关闭恢复保护。
