# 核心整合第五阶段：审查验证、记忆与经验沉淀

日期：2026-10-30。对应既定六阶段方案的第五阶段。本阶段扩展现有 Collaboration、原生审批和 Harness 提示组装；没有安装 Meta_Kim Skill，没有引入另一套调度器或 Web 控制台。

## 审查、验证和验收

- 新增 `emergence_audit` 与 `/audit run <任务 ID> review|verify [窗口]`。省略窗口时创建独立会话；指定窗口必须是同项目的空闲执行窗口，不能是原实施会话。审查与验证不能共用会话。一个任务每种最多两次，不允许“审查审查任务”的递归派工。
- 使用已校验目录中的 Prism、Warden、Sentinel 职责摘要辅助审查。审查只读；验证继承原任务及当前权限，写文件和继续委派被限制，命令仍须审批。角色名字和模型输出不能扩大权限。
- Harness 实际工具执行记录生成证据，包含调用 ID、工具类型、结果/参数摘要、退出码及适用的文件摘要。模型用 `emergence_assess` 逐项提交验收编号、结论、实际回执 ID 和说明。伪造 ID、其他会话回执、成功结论引用失败回执、遗漏验收项均拒绝。
- 审查通过需要实际读取回执；验证通过需要实际命令返回且退出码为 0。后台未结束、取消、超时、非零退出不算通过。记录提交还不等于轮次成功，最终仍受工具错误和执行回执约束。
- 证据绑定任务批次、契约、产物和来源会话；查询、模型验收和经验写入前重新核对。原生写文件、报告中列出的产物、审查引用的读取文件发生变化，旧结论不再有效。
- 模型 `emergence_review` 不能再靠一段文字放行任务，必须有当前版本的独立审查和验证。用户 `/task accept` 保留主动验收权，单独记录为 user；不会因此把未做的独立验证标成通过。
- 修复继续使用原有有界任务链和权限。修复后产生新任务、新版本，旧证据不继承。等待验收的任务图允许增添审查窗口，但不能趁机更换已有主控、执行者或移除正在使用的窗口。

查看方式：`/audit` 列出任务；`/audit show <ID>` 分别展示执行结束、审查、验证、用户验收；`/audit history <ID>` 显示关联任务和当前可加载会话最近 100 条事件，只读，不重放操作。任务侧栏增加审查来源、逐项结论及复查入口；现有视觉布局保持不变。

## 三级记忆与生命周期

内置本地记忆位于应用 home 的 `core/memory/records.json`，schema 1。按实际项目路径归一化：session 只在本项目本会话可见，project 同项目共享，personal 仅允许用户显式批准共享的通用 preference。项目事实和策略不能直接放入个人层。

任务衍生经验只进入项目或会话层；需要跨项目共享的通用偏好，由用户明确提交 personal preference 候选。窗口内切换实际工作目录后，旧项目来源不能作为新项目经验写入。

使用 Librarian / Chrysalis 的职责边界形成以下流程：候选 → 来源证据检查 → 预览及用户批准 → 有效参考 → 纠错/回退重新批准或遗忘。模型只能提交有实际任务证据的候选，不能调用批准工具。

常用命令：

```text
/memory
/memory propose project fact "项目的测试命令是 npm test"
/memory propose personal preference "默认使用中文交流"
/memory approve <ID>
/memory show <ID>
/memory search "关键词"
/memory correct <ID> "纠正后的内容"
/memory history <ID>
/memory rollback <ID> <历史版本>
/memory forget <ID>
/memory status
```

- 候选不会被召回。批准、纠错、回退、遗忘都预览原文/新内容和来源，采用原生弹窗；Enter 默认取消，方向键选择后 Enter 确认，Esc 取消。
- 用户自己提交的内容标记为用户来源；模型生成的经验必须关联同项目、当前有效的独立审查和验证。批准时再次核对，产物失效后停止召回相关经验。经验是参考数据，不是执行指令。
- policy 与事实、偏好分开保存。即使批准，也只保存为策略建议，不自动注入请求，不改 EMERGENCE.md、工具、角色、配置或权限。实际规则修改仍走已有明确编辑与审批流程。
- 纠错和历史回退都重新进入候选，不能沿用旧批准。遗忘删除记忆正文和历史正文，仅保留 ID/版本墓碑，不能从 memory history/rollback 恢复。
- 每次模型请求组装时重新读取有效记忆，单次最多检查 12 条，记忆数据最多 4000 字符，加有界职责说明。没有有效记忆时不增加记忆正文，不增加模型请求。查询工具返回索引，正文通过当前有效参考区提供，不重复复制进历史工具回执。
- 记录使用进程间租约、原子替换、版本比较；并发修改不会无声覆盖，审批期间权限、内容或项目变更会使旧确认失效。损坏文件和链接路径拒绝使用，原文件保留。单条 2000 字、最近 10 个历史版本、500 条记录、总文件 6 MB 上限。
- 已配置凭据和常见密钥形式会被阻止写入记忆。此检查不能识别所有可能的敏感数据，用户仍可在批准前看到完整待保存内容。

## 外部能力与范围

本地记忆可独立使用。`/capabilities` 登记可选 kim-service、Graphify 及实际配置的 MCP 状态，继续通过既有 MCP 连接、工具激活和权限链调用外部服务。本阶段没有擅自配置外部服务器，也不自动上传或同步本地记忆；`/memory status` 明确显示未绑定专用记忆同步。不能把服务配置存在等同于语义接口已经验证。

当前模型验证仍是“实际回执支持的模型结论”：退出码为 0 不自动证明检查命令覆盖了全部需求，必须结合逐项说明和实际日志审查；没有声称机械检查能证明任意任务正确。文件覆盖限已知产物及引用读取路径，未声明的外部系统状态仍需专门验证。

遗忘是本地记忆服务的逻辑遗忘，不是对磁盘备份的安全擦除，也不删除用户以前输入的聊天记录、模型曾输出的文字或已经发送给外部供应商的数据。后续请求不再由记忆模块提供已遗忘内容；不承诺抹除全部历史对话中的引用。

旧任务自动补充空证据字段，不伪造历史审查结果。继续使用第四阶段 SQLite 与备份策略；本阶段未增加 npm 依赖。关闭核心后停止新的记忆写入、召回及审查派发，已有任务记录保留。回退代码前退出应用并备份整个 home；旧版本不识别新任务字段时，应搭配更新前的成套 home 备份恢复，不删除记忆库来强行绕过校验。
