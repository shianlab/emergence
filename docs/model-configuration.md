# 可视化模型配置

模型配置是涌现随附的 Windows 原生小工具，管理模型库、当前工作台窗口，以及新窗口默认模型。界面全部采用 Windows Forms 系统控件，不使用网页、WebView、Electron 或浏览器。规划见 `specs/model-configuration`。

界面按最新要求收为约 520 逻辑像素宽的白底浅灰小窗，高度随内容调整，超出屏幕时在页内滚动；顶部只有“模型库 / 分配”两个页签，无侧栏和大标题。默认显示模型列表，点击模型进入编辑、保存后返回；窗口默认规则收在折叠区。TUI 的深色界面不受影响。

## 打开

在项目根目录双击 **涌现模型配置.exe** 即可，无需手动启动终端。发行包也在根目录提供同名入口；此小工具随项目使用，请保留涌现运行文件。需要 Windows x64 与 .NET Framework 4.8，不需要额外安装网页运行环境。

```powershell
emergence model-config
# 等价入口
emergence config ui
```

开发时可在 `emergence` 工程目录运行 `npm run models:ui`，先构建再打开同一原生窗口。`npm run build` 使用 Windows 自带的 Framework 编译器生成原生 WinExe，单个程序约 73 KB；复用涌现自带 Node 后端，不另外打包一套运行时。关闭独立小窗会自动退出对应配置服务。

管理正在运行的主窗口及副窗口时，在目标工作台输入 `/model-config`。首页也有“模型配置”入口，Ctrl+P 命令列表同样可用。直接输入“打开模型配置”“怎么配置模型？”或“模型怎么配置啊”也会打开工具，不产生模型请求。一般开发问题仍交给 Agent。

## 配置模型

1. 点击“添加模型”，选择厂商及普通 API / Coding Plan 接入方式；预设自动填写地址、协议、模型和密钥环境变量名，粘贴 Key 后测试、保存即可。已有 8 家国内厂商的 15 个预设，另有自定义兼容接口。可修改模型名；预设的官方文档核对日期不代表账号已经取得模型权限。
2. 协议支持 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google 的 OpenAI 兼容接口。基础地址不包含具体请求路径。Anthropic 输入根地址或以 `/v1` 结尾的地址均可，测试与运行时统一请求 `/v1/messages`。Google 使用官方 `/v1beta/openai` 路线，填写到 `/v1beta` 或 `/v1beta/openai` 均可。
3. 可使用已有环境变量。Windows 也可输入新密钥，保存时通过 DPAPI 绑定当前 Windows 用户加密；留空保留原值，显式 shell 环境变量优先。界面会标明“环境变量优先”，新保存的 Key 被环境变量覆盖时明确提示；需取消该环境变量并重启涌现才能切换为保存值。其他系统使用环境变量，表单密钥只可临时测试。
4. “测试连接”使用表单当前内容发起一次小型真实推理请求，可能产生少量 API 用量。结果包含耗时和鉴权、限流、地址/模型、协议、网络、超时错误。测试不自动保存，也不验证工具或图像能力。
5. 从当前工作台打开时，保存会即时更新运行时路由；更改正在使用的配置影响下一轮请求。保存模型或默认规则时要求工作台、子代理、工具及关联任务空闲。

配置 ID 是稳定引用，编辑时只读。更换 ID 请新增模型。删除前先解除默认规则和当前窗口引用；删除模型不会清除可能被其他模型共用的密钥。

## 窗口分配

列表显示实际窗口编号、稳定 ID、主/副/独立角色、状态和目录，包含后台窗口。选择后点击“应用”，只切换该空闲窗口，保留历史、会话及目录。运行中、待确认、子代理运行、协作关联或恢复失败时拒绝切换。

| 默认规则 | 生效时机 |
| --- | --- |
| 全局默认 | 无其他覆盖时的默认模型 |
| 单窗口 | 新启动工作台的首个会话，显式 `--model` 优先 |
| 主窗口 | 通过右键/标题栏设为新主窗口时使用；已是主窗口时不覆盖手动选择 |
| 副窗口 | 新建副窗口时使用；未设置则继承来源窗口模型 |
| 窗口 02–16 | 新建对应编号的窗口时优先于副窗口默认 |

保存规则本身不会更换已有窗口模型。恢复工作台保留其原模型；模板与显式分屏模型优先。窗口编号是当前列表顺序，关闭后重新编号；会话关联仍用稳定 ID。

独立命令行模式管理共享配置与默认规则，不能直接操作另一个运行中的进程。即时分配请从目标工作台打开工具；其他已启动进程需要重启以加载新的配置。

## 文件和生命周期

- `%USERPROFILE%\.emergence\config.json` 保存模型连接与 `windowModels` 默认规则，不含 API 密钥。
- 同目录 `credentials.dpapi.json` 保存 Windows 加密凭据。
- `workspaces` 沿用原有窗口、会话、模型及布局保存。
- `--home` / `EMERGENCE_HOME` 仍支持隔离环境。

原生界面与配置后端通过只监听 `127.0.0.1` 随机端口的 JSON 接口通信，并验证会话令牌与请求来源。后端不提供 HTML/JS/CSS 页面。服务令牌通过私有进程管道传给原生窗口，不进入进程参数；模型 Key 不回显、不进入 URL。独立窗口关闭时结束自己启动的隐藏后端；TUI 打开的窗口关闭后，工作台继续运行，再次输入 `/model-config` 可重开。退出 TUI 会关闭它启动的原生窗口。

修改使用原有租约和原子写入；配置指纹防止多个编辑页互相覆盖。其他偏好与编排设置不会被表单整份覆盖。

## 验证命令

```powershell
npm run test:model-config
npm run test:model-config:runtime
npm run inspect:model-config
npm run test:model-config:native
npm run typecheck
npm run build
# 明确发送真实请求：每个已配置模型 2 次小请求，最多检查前 4 个模型
npm run test:model-config:live
```

普通测试与 `inspect:model-config` 使用隔离临时目录与本机 HTTP 服务，不调用付费 API。运行时验证使用实际 Harness、llm-pi-ai、会话和动态 settings，检查路由新增/编辑、窗口切换与历史、默认规则、后台窗口、忙碌拒绝，以及 Windows 下新增/更换密钥后真正发出的请求。全面巡检另外逐项检查 15 个国内预设，并验证重启 CLI 后可解密使用保存的 Key。原生专项会打开隔离小窗，自动检查附加、重开、管道关闭；独立小窗出现后手动点关闭，继续验证后台退出及配置未被改写。`test:model-config:live` 才会读取现有配置和凭据访问真实供应商，不修改个人配置；会产生少量 API 用量。原生交付见 [原生窗口报告](model-configuration-native-report.md)，后端原有巡检见 [2026-10-30 巡检报告](model-configuration-audit-2026-10-30.md)。
