# 安装改进第三阶段：版本发现与在线更新

本轮完成版本发现服务、中文更新菜单、签名验证与在线更新接入。实现和本机隔离验收完成，尚未发布 GitHub，也未覆盖本机实际安装。源码版本仍为 1.0.1，仅作本地候选；正式新版本和外部电脑验收属于第四阶段。

## 产品行为

- 托管安装启动后后台检查，持续运行每 6 小时检查；多个进程共享缓存和互斥锁，独立分屏共享一个服务。检查最长 5 秒，失败也限频，不阻塞启动或任务。
- 首页和工作台使用同一套中文更新选项：检查、查看说明、立即更新、稍后、开关自动检查。支持 Enter 和 Esc，重新打开默认选中检查，不记忆上次安装按钮；更新不发起模型请求、不改变输入草稿。
- `emergence update --check` 查询版本，`emergence update` 在线安装，`/update` 打开菜单。原有离线维护入口继续使用；开发目录和便携包不会被自动覆盖。
- 安装显示实际下载和部署进度，新版准备完毕才提示下次启动生效。当前会话继续使用原版本；只有安装回执与实际启动指针一致才显示就绪，回退后不会残留假成功。
- `doctor` 只读展示安装来源和更新状态。更新失败记录有限、脱敏诊断，用户无须提供模型密钥排查安装。

## 结构与安全审查

`src/app/updates/` 分离协议签名、传输、存储、服务、运行适配及中文投影。EntryUI 拥有服务生命周期，界面只订阅；关闭释放定时器、监听器和元数据请求。下载复用第一阶段，部署复用第二阶段事务，没有新增第二套安装引擎，也没有接回跨窗口控制。职责与发布操作见[维护说明](structure/update-maintenance.md)。

稳定版清单使用 RSA-3072 / SHA-256 签名；应用和独立 PowerShell 引导分别验证，打包核对公钥表一致。发布私钥仅以 Windows 当前用户 DPAPI 密文保存在源码之外。清单限制产品、平台、版本、固定仓库地址、大小、哈希、时间和发行序号；拒绝伪造、过期、撤销密钥、错误平台、序号倒退及同序号内容变化。元数据限制 64 KiB，不接受跳转，不携带项目、对话或密钥。

更新缓存写入核对安装所有权，卸载和检查、安装共享系统互斥机制。卸载仅清理已识别的更新状态和请求文件，未知文件保留；已卸载目录不会被迟到的检查重新创建。发布输入生成工具拒绝覆盖既有 1.0.1 通道，生成文件与上传分开，稳定指针留待资产发布验证后更新。

在线验收运行生产下载、签名与安装事务，只在隔离传输层指向本地 HTTP 服务并使用临时测试公钥；不使用真实模型 API 或用户密钥。测试中发现包装脚本缺少 UTF-8 BOM，Windows PowerShell 5.1 将中文路径误解码；修正测试包装后完整重跑通过，生产引导原本已有 BOM。同时补齐子进程失败诊断，避免只返回无法定位的退出码。没有因此放宽签名或安装检查。

其余巡检修正包含：同序号清单不可替换、检查失败缓存限频、卸载并发保护、菜单重复 Enter 防重入、回退后就绪状态复核、检查结束不向关闭界面发布事件。对应测试覆盖真实超时、并行客户端、签名轮换重叠/撤销、安装失败持久化和实际 Windows 互斥。
