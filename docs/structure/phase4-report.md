## 随职责迁移修正的边界

1. **会话切换不是完整的单一操作。** 旧实现只检查 Agent 正在运行，不能挡住两个异步切换交叠；候选绑定后的异常也缺少统一回退。现在切换由一个进行中的操作拥有，候选失败恢复旧句柄/配置并释放候选；关闭等待切换结束。切换、取消和关闭期间向调度及配置调用方呈现忙碌状态。
2. **关闭途中抛错可能跳过后续清理。** 现在规则初始化、历史刷新、根 Agent、规划、KIM、诊断、子代理租约和订阅逐项收尾，收集错误后统一报告。重复关闭/取消复用同一操作。
3. **异步模型查询可能落到新会话。** `/model` 查询返回后重新检查原会话身份、切换状态和忙碌状态；旧选择不能改变替换后的会话。
4. **规划内部对象可以被多个调用方修改。** 工具适配器改用分析、接纳、预算及回执操作；界面、清单、执行调用和测试读取分离副本。连分析输入、提交返回值也不与权威状态共享可变对象。
5. **迟到的规划结果可能修改新请求。** 计划检查与执行使用原请求/目录绑定；旧检查成功、旧检查失败、旧执行回执都不能覆盖新请求。草案提交不会回退检查期间增加的读取预算与回执；迟到的旧请求工具回执也不能变成新请求证据。

需求来源、KIM 自动分析与澄清、本会话计划准入、真实执行回执、拒绝/取消/超时和未知副作用不重放的规则继续保留。PlanStore 格式、用户模型及密钥、历史数据和视觉未作迁移。本次没有修改依赖、发行版本、安装方式或发布标签。

完整矩阵期间的复审补到了“切换中应向其他调用方呈现忙碌”的边界。继续核对通知顺序时，新增断言复现了取消已经结束、最后一次通知却仍呈现忙碌的问题；修正为取消操作结算后发出状态通知。两轮中间矩阵主动停止，分别保留 interim-matrix/interim-checks 和 interim-transition 记录，失败断言见 cancel-notification-before.log。修正并通过生命周期测试后重新冻结，从头执行最终完整矩阵，不拼接不同版本的结果。

随后完整矩阵为 40/41，experience-e1-ui 遇到原生缓冲区 OutputBusy。检查已安装 OpenTUI 的测试接口和脚本发现，关闭窗口后直接截取末帧，没有等待重新渲染完成；catch 中再次同步截图还会覆盖原始异常。测试现改用 waitForFrame 检查审批画面，在全部交互断言完成后暂停绘制并等待 renderer.idle 再截取最终帧，catch 直接保留错误堆栈。不能在持续动画的每一步等待整个 renderer 空闲，因此没有把全局 idle 加入每步 flush。产品 TUI 未改，原有全部审批、键盘、草稿和关闭断言保留，修正后定向连续三次通过，再重跑完整矩阵。失败轮保存在 native-output-failure.json/log，定向结果为 native-output-1/2/3.log。
