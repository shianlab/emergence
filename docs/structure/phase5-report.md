## 职责迁移

| 原集中位置 | 当前归属 |
| --- | --- |
| workspace-ui 内的单窗控件、输入提交和展示字段 | pane-view / pane-view-state；明确回调与只读视图注册表，保留原窗口及会话绑定 |
| 全局键盘与粘贴处理 | workspace-input；单一模态状态配合明确的操作回调，不复制审批或执行状态 |
| 单窗提示、底栏和品牌动效缓存 | pane-notice / workspace-brand；只消费原有事实，品牌缓存封装在模块内部 |
| 工作台布局、导航菜单及订阅/定时器 | workspace-ui 保留组装和唯一释放入口，复用既有 navigation、command-list、task-inspector、geometry 等组件 |
| 原生 Program 的连接、后端进程和协议转换 | Connection、Json、Choice；Program 仅保留启动入口与顶层错误处理 |
| 原生窗口、页面、编辑及保存 | ConfigurationForm / ConfigurationPages / ConfigurationActions；独立 ModelDraft 管理编辑数据 |
| 只编译 Program.cs 的构建规则 | 自动发现全部原生 C# 文件，排序后的文件名与内容进入指纹和编译参数 |

17 个实现、构建和测试文件的变更前后哈希见 [第五阶段迁移清单](phase5-migration-catalog.json)。当前状态归属、回调与释放顺序见 [界面维护指南](ui-maintenance.md)。被提取的实现已从旧入口退出，没有保留转导出外壳或第二套执行循环。

workspace-ui 从 1,653 行变为 1,018 行。剩余部分仍承担工作台级导航、布局及刷新协调；没有把所有闭包变量打包后传给每个模块。输入模块只声明实际需要的工作台成员，视图工厂采用命名回调，品牌缓存独立封装。UI 模态状态由组装层创建一次，菜单呈现与按键路由共同使用；这是明确的 UI 协调状态，不另造业务状态库。

原生工具的三份 Form 文件属于同一个 partial Form，控件、加载配置和默认分配草稿仍只有一份。编辑草稿独立出来，通过复制隔离加载配置，重新编辑清空上一份临时密钥；连接及草稿可以不创建窗口独立测试。刷新、删除、测试连接、保存模型、保存默认及应用窗口模型六个异步操作使用命名方法，共用原来的串行操作入口。

## 资源与边界修正

- 原生轮询增加进行中标记，慢请求不会叠加；编辑/默认分配未保存时仍不覆盖草稿。
- 关闭明确停止并释放轮询、清空编辑器密钥并释放品牌图像；连接允许重复释放。
- 连接释放后拒绝新调用及迟到响应，操作收尾不再更新已关闭控件。避免服务响应晚于窗口关闭时继续渲染页面。
- 新增后台测试的临时编译目录在结束时删除；不向用户配置写测试模型或密钥。

保留原 HTTP 本机地址/令牌验证、配置服务版本冲突检查、DPAPI、.NET Framework 4.8 及原生控件。所有 C# 文件都参与构建指纹和编译；产物路径未变，现有 release-pack 的 exe/config 清单继续包含完整编译结果。本轮不生成或发布新的安装包。

TUI 的视觉、首页首次提交流程、中文命令推荐、审批、焦点、分屏和关闭语义保持。主控窗口及跨窗控制继续退役。键盘/粘贴监听、工作台事件与刷新定时器仍由挂载入口统一注册及释放，模块提取没有增加后台循环。

## 范围与后续

本轮只做源码修改、后台构建和自动测试，没有控制鼠标或桌面。OpenTUI 与 ConPTY 提供自动交互证据；Windows Forms 验证为后台编译、草稿/连接测试和本地配置服务协议，不冒充人工点击验收。在线付费模型、真实桌面点击、干净安装升级及发布候选包仍属于后续最终验收范围。

仍保留的技术债有：工作台组装函数较长，C# 页面布局部分沿用原有紧凑写法，内部类型耦合组仍存在。没有将这些事实写成“全仓库已完全规范”。第六阶段统一多语言格式、静态检查及维护规则；第七阶段完成最终结构复审、实际环境和候选包验收。
