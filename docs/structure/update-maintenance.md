# 版本发现与在线更新维护

此层属于安装维护，不属于 Agent、KIM、工具审批或跨窗口编排。独立分屏共享更新服务，不因此获得互相控制能力。

## 职责与状态

| 文件 | 唯一职责 |
| --- | --- |
| `src/app/updates/manifest.ts`、`trust.json` | 稳定版协议、版本顺序、签名和来源验证、内置公钥 |
| `transport.ts` | 固定官方地址的小型清单请求；5 秒信号、64 KiB 上限、不接受跳转 |
| `storage.ts` | 托管/便携/开发安装识别、更新专用状态读写、路径与所有权检查 |
| `service.ts` | 检查、偏好、安装状态及生命周期；独立于模型与会话任务 |
| `runtime.ts` | 调用已打包的独立引导脚本，将真实进度回传；不另写安装事务 |
| `presentation.ts` | 中文提示和操作选项，首页及工作台共用 |
| `scripts/release-channel.ts`、`release-signing.ts` | 生成并签名本地发行输入，绝不自动发布 |

EntryUI 拥有一个 UpdateService，从首页到工作台沿用；分屏不新建服务。首页沿用原菜单状态，工作台沿用既有导航模态。空闲时显示新版本提示，不抢焦点；用户主动安装时显示真实进度。菜单默认选择“检查更新”，不会记住上次“立即更新”的位置。关闭释放定时器、观察者并取消元数据请求；已经开始的安装不会因关闭菜单而中断。进程强制退出按第二阶段的事务恢复规则处理。

受管安装根的 `updates/state.json` 保存检查时间、签名信封、最高发行序号、自动检查偏好、延后版本、更新回执与最近失败。使用原子替换和跨进程 IPC 锁；不修改严格的模型配置 schema。检查缓存默认 6 小时，手动检查绕过缓存但并发请求合并。失败也限频，断网时不不断重试。关闭自动检查不禁止手动检查。

`updates/failure.json` 保存安装子进程失败的有限、脱敏诊断；更新请求临时文件只存公开签名清单，结束后删除。`doctor` 只读取安装来源及更新状态，不联网、不解密模型密钥。当前版本来自运行程序；“更新已就绪”还要核对实际安装指针，程序回退后不会继续显示旧缓存里的假成功。

下载使用第一阶段的缓存、限时重试、校验和 ZIP 路径检查。在线入口的签名在应用与独立脚本中分别验证，哈希与字节数必须吻合，解压后的产品与版本必须匹配。部署调用第二阶段同一安装管理器。安装、检查与卸载共用相应操作锁；卸载不会和正在下载的更新争抢目录。未知文件仍保留，不扩大清理范围。

## 信任与签名

签名为 RSA-3072 / SHA-256（PKCS#1 v1.5），信封为 `payload`（原始 JSON 字节的 Base64）及 `signatures` 数组。验证原始字节，不用重新序列化代替签名原文。实现依据为 [Node.js crypto 官方文档](https://nodejs.org/api/crypto.html)，Windows PowerShell 5.1 使用系统 RSA 实现交叉验证。

应用和 bootstrap 内置同一公钥表；打包时核对一致性。私钥仅以当前 Windows 用户 DPAPI 密文保存于 `%USERPROFILE%\.emergence-publisher\signing.dpapi.json`，不在源码、发行包或 GitHub 中。发布工具只通过管道解密，不能把私钥作为命令行参数、环境日志或构建附件。

轮换必须先由旧受信密钥签名包含新公钥的客户端，再切换签名者；重叠期可用多签名信封。撤销通过新客户端的受信表标记 `revoked`，未知或撤销密钥不能验证。测试覆盖重叠、未知和撤销密钥。**没有远端任意导入公钥的后门；已失去所有受信密钥的旧客户端需要可信渠道手动迁移。** DPAPI 文件绑定发布者 Windows 用户，不能把它当成可跨机器直接使用的明文密钥备份。

清单包含产品、平台、稳定语义版本、递增序号、发布日期、到期日、最低安装协议、固定仓库资产 URL、字节数、SHA-256、说明和固定发行页地址。拒绝预发布、过期、错误平台、签名错误、序号倒退和同一序号内容变化。缓存只复用经验证的清单，不信任 README、搜索结果或模型回答。请求不包含会话、模型密钥或项目路径。

## 发布与维护入口

```text
npm run test:updates
npm run test:updates:tui
npm run test:updates:online
npm run release:pack
npm run release:channel -- <更新说明.md> <递增发行序号>
```

发布输入生成在 `artifacts/releases/channel-版本-序号/`。`update.json` 随版本资产不可变发布，`stable.json` 最后放到仓库 `releases/stable.json`。必须先验证 ZIP、签名、完整安装和匿名下载，再更新稳定指针。清单默认有效期 90 天；续期需要重新签名并增加序号，不能修改同一序号的内容。正式签名只使用发行包指纹完全一致的输入。

根引导的 `-Latest` 和 1.0.2 起的指定版本使用相同签名清单。1.0.1 及更早的不可变发行物保留历史校验文件兼容。1.02 默认读取稳定通道，只有显式指定 `-Version` 才固定版本；后续发行继续遵守先验证公开资产、再同步主分支入口和稳定指针的顺序。正式包与核验记录见[1.02 发行核验](../release-audit-1.0.2-2026-11-17.md)。

真实包测试只在隔离包装层替换传输地址与临时测试公钥，运行生产验证器、下载器和安装事务，不打开或接管桌面，不上传任何资产。
