# TUI 与原生模型配置维护指南

本页对应结构整理第五阶段。产品继续是独立多窗口；布局、焦点和模型分配不授予跨窗口执行权。

## TUI 职责与状态

| 模块 | 负责什么 | 状态与操作边界 |
| --- | --- | --- |
| `app/workspace-ui.ts` | 工作台组装、导航/菜单呈现、布局与刷新、订阅与释放 | 拥有唯一视图注册表、布局、模态状态、两个刷新定时器；连接既有 command-list、navigation、task-inspector 等组件 |
| `app/tui/workspace-input.ts` | 键盘、粘贴与操作优先级路由 | 使用明确的 InputHost 回调和按实际成员收窄的 WorkspaceController 接口，不创建另一套工作台或审批状态 |
| `app/tui/pane-view.ts` | 每个窗口的控件创建、输入提交、局部事件绑定 | 只读访问视图注册表；通过宿主回调打开菜单、报告错误和刷新。异步提交失败恢复草稿时继续校验原窗口及会话身份 |
| `app/tui/pane-view-state.ts` | 每窗 UI 状态契约 | 控件引用、消息投影、输入和滚动等展示状态；不拥有 Agent 会话或工具执行事实 |
| `app/tui/pane-notice.ts` | 运行提示、回执时间及 Tokens 底栏投影 | 使用既有业务事实；不将缺失 Token 回执伪装为零，不另外维护执行状态 |
| `app/tui/workspace-brand.ts` | 对话标记的状态与轻微动效 | 私有保存品牌显示缓存；工作台只调用绘制函数，并拥有触发定时器 |

`WorkspaceModalState` 由工作台挂载创建一次，记录命令窗口/会话身份、导航、权限菜单、右键菜单目标及提交防抖时间。菜单呈现与输入路由使用同一对象，这是 UI 协调状态，不是业务状态副本。不要在输入模块新增一个平行的菜单状态库。

导航、菜单和布局仍由工作台组装层协调，相关条目、列表控件、几何计算与任务详情复用既有模块。它们并未被机械地各拆成一个包含同样闭包变量的类。后续新增操作须优先放入对应组件，通过命名回调连接；不要把全部控制器私有字段装进通用宿主接口。

输入优先级保持右键菜单、权限确认/提交保护、命令导航、当前窗口输入及全局操作的原规则。审批回答仍由 InteractionQueue 校验；不能用 UI 当前焦点代替请求身份校验。

### 同步呈现与脱敏

工作台的一次同步刷新使用 `createRedactor()` 读取当前凭据，再显式传给窗口、标题、提示和底栏投影，避免每个字段重复枚举 Windows 环境变量。这个函数只在当前调用栈内使用，不保存到控件、控制器、定时器或跨越 await；下一次刷新重新读取凭据。独立诊断继续使用 `safeError()`，每次读取当前环境，新增或轮换密钥立即生效。两条入口共用同一份 URL、Authorization 和终端控制字符清理实现。

### TUI 资源收尾

`mountWorkspaceUI.dispose()` 是挂载资源的唯一收尾入口，允许重复调用：

1. 标记释放并停止状态、品牌定时器。
2. 保存各窗草稿与滚动位置。
3. 移除工作台、渲染器、键盘及粘贴监听。
4. 释放 terminalActions、消息呈现资源和整棵控件树。

`startWorkspaceUI` 随后销毁由它创建的 renderer。视图工厂与输入路由不额外注册全局监听或建立后台定时器；资源归属不会随着代码提取而分散。

## Windows Forms 职责与状态

| 文件 | 责任 |
| --- | --- |
| `Program.cs` | DPI/标准流初始化、连接启动、窗口运行与顶层异常 |
| `Connection.cs` | 本机服务启动/附加、地址及令牌验证、HTTP 调用、连接/自有后端进程释放 |
| `Json.cs`、`Choice.cs` | 既有 JSON 协议转换和原生下拉选项值 |
| `ModelDraft.cs` | 编辑草稿隔离、编辑目标、临时密钥、脏状态和本地必填校验 |
| `ConfigurationForm.cs` | 原生窗口、控件生命周期、串行操作/轮询门控、全局配置快照及默认分配草稿 |
| `ConfigurationPages.cs` | 模型库/编辑页/分配页原生控件与控件值采集 |
| `ConfigurationActions.cs` | 刷新、删除、测试、保存模型、保存默认和应用窗口模型六个命名操作 |

Form、Pages、Actions 是同一个 partial Form：控件和默认分配状态只保存一份；它们不是三套状态同步系统。模型编辑使用独立 ModelDraft，开始编辑会复制数据并清除上一份密钥；保存时仍走配置服务的权威校验、版本冲突检查及 DPAPI。客户端本地校验只用于交互提示，不能替代服务端校验。

所有写操作从 `Run` 进入，共用 busy/disconnected 门控及错误提示。轮询有独立的进行中标记，避免慢响应重叠；编辑中或默认规则未保存时不刷新覆盖草稿。关闭停止并释放轮询、清空临时密钥、释放品牌图像及连接。Connection.Dispose 幂等，独立启动的后端按原协议关闭；附加到现有服务时不关闭整个工作台服务。

Connection.Call 在释放前及响应读取后检查生命周期。窗口强制关闭后的迟到响应不得返回页面动作；Run 不再向已关闭控件写入错误或启用状态。

## 构建与验证

`scripts/build-model-config.ts` 按排序后的 `native/model-config/*.cs` 自动发现源文件；文件名、内容、manifest、品牌资源及构建脚本共同参与指纹，所有发现的 C# 文件均传给原编译器。仍输出原来的 exe/config，打包继续包含 `dist/model-config`，不改变 .NET Framework 4.8、原生控件、安装入口和用户配置格式。

相关检查使用 `npm run check`、`npm test`、`npm run inspect:full`。新增 native-model-structure 测试在临时目录后台编译全部 C# 源文件，通过控制台入口验证草稿、校验、重复释放及迟到响应；不创建 Form，不显示窗口，测试结束删除自己的临时目录。

自动验收涵盖 OpenTUI 测试渲染与后台 ConPTY，以及模型服务协议。它不能替代用户在实际 Windows Forms 上的人工点击验收；用户要求自行操作桌面，本轮不使用桌面控制工具。
