# 模型配置工具实现与验证

日期：2026-10-30。使用方式见 [模型配置指南](model-configuration.md)，需求、设计与任务见 `specs/model-configuration`。

本文件保留初次实现验证记录。后续白底紧凑窗口、15 个国内预设和真实供应商验收，以 [全面巡检报告](model-configuration-audit-2026-10-30.md) 为准。

用户随后要求界面控件全部原生实现，当前已移除网页入口，最新版见 [Windows 原生工具报告](model-configuration-native-report.md)。下方网页验收属于历史记录。

## 实现

- 随涌现打包的本机图形界面，白底灰阶编辑排版，顶部复用定稿手写像素标识；模型库与窗口分配两个页签。
- `emergence model-config` / `emergence config ui` 独立启动；首页按钮、Ctrl+P `/model-config` 和明确自然语言请求打开同一工具。
- 模型新增/编辑/删除、四协议连接测试、DPAPI 凭据保存；旧配置默认兼容，不自动迁移原文件。
- 当前工作台实际主窗口、副窗口及后台窗口列表，独立应用模型并保留历史；全局、单窗口、主窗口、副窗口和第 2–16 窗口默认规则。
- Harness 原有 llm-pi-ai settings 动态更新，不增加推理代理。CredentialProvider 的可释放装饰器解决固定启动环境导致新密钥不能即时使用的问题，其他凭据空间保持原行为。
- 配置租约、原子写入、过期编辑拒绝、工作台互斥、模型历史兼容检查；运行时更新失败回滚模型字段，同时保留并行写入的其他偏好。密钥与配置是两个存储事务，若密钥已保存而后续配置失败，错误明确提示密钥已保存，可修正配置重试。
- 只监听 loopback 随机端口，验证 Host/Origin/Bearer，限制请求与响应大小，使用本地静态资源和 CSP。API 不回传保存的密钥或供应商错误正文。

## 边界

独立模式只能修改共享配置与默认规则；实时分配需要从目标 TUI 工作台打开。旧的已运行 TUI 进程需重启一次才能加载本轮新增入口，其他进程不通过本工具强制重载。真实供应商权限、网络与具体模型能力由用户在界面点击连接测试验证；本轮四协议验证使用本机服务。
