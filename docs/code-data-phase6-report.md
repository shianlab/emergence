# Code / Data 第六阶段：跨领域联调与统一验收

日期：2026-10-31。状态：第六阶段工程联调与本机巡检完成，已重新构建。确定性检查通过；真实模型任务仍有未通过样本，下面逐项保留，不宣称全场景稳定或可以直接发布。

最终记录见 [验收汇总与源码哈希](../artifacts/code-data-phase6/final-validation.json)。本轮修复了窗口能力发现、数据交付/版本传递、审查竞态、Token 截断假完成和脱敏性能问题。当前可继续在本机反复调试；远程 SQL 适配和模型方法选择的稳定性仍有明确边界。

## 已发现并修复的集成缺口

1. 新窗口只在收到首条输入后注册 Code/Data 工具，主控在派工前查能力会误判“不支持数据分析”。现在会话建立时注册原生能力，窗口空闲时也能被准确匹配；权限与禁用规则仍优先。
2. 下游原先主要核对普通写入产物，漏掉原生分析输入、业务口径和隔离报告目录的版本。下游启动前现在走同一证据校验，变化即阻塞；主控整体完成前也复核数据产物。
3. 依赖和独立审查上下文补入宿主生成的原生数据交付索引：实际输入、请求/结果/口径/报告路径及哈希。保留持久任务与回执，不另建调度器。
4. 独立审查异步核对哈希期间可能恰好结束，旧状态快照与新终态混用会误报“无有效证据”。现在检测状态变化并在下一次协调循环复核，不伪造通过或重复派发。
5. 供应商返回 `max-tokens` 时，原先普通会话可能显示“本轮已完成”，`--print` 也返回 0。现在保留明确的“本轮未完成”错误，退出码为 1，不自动重试或重放副作用；受控协议故障测试验证了这一行为。
6. 最终主控汇总把原生报告纳入宿主交付清单，避免原生分析成功却写成“无文件产物”。
7. 长会话 CPU 采样定位到脱敏函数反复读取全部 Windows 环境变量。改为枚举名称后仅读取可能的凭据变量；仍在每次调用读取当前值，新增/轮换密钥立即生效，不缓存旧值、不关闭脱敏。2,000 次本机微测从约 201 ms 降至 78 ms；不把微测比例当作整机提速比例，最终以五分钟实测判定。

混合场景使用实际 Python 脚本、文件、数据引擎和独立审查：修复把退款取绝对值的错误 → 执行项目检查并生成 clean.csv → 原生计算合计 8 → 独立重算和读取审查 → 自动验收。以两个初始窗口启动，独立审查按现有策略分配新的隔离会话；不是“全程最多两个会话”的容量测试。测试只提供受控模型响应，不替主控调用派工、审查或验收。原始 raw.csv 不变。另覆盖原生任务未声明 artifacts 时，源数据变化仍必须阻止下游执行；新窗口能力与 `emergence_data_*` 禁用规则也有检查。

## 数据规模与安全

实际固定 Python worker 在 1,000 与 10,000 行 CSV 上各做三次 DuckDB 汇总，结果与手工公式一致；10,001 行各三次明确拒绝，未静默截断。当前 1 万行查询约 16–18 秒，峰值工作集约 56 MiB；这是受限本机引擎测试，不能外推到百万行。内存测量位于真正执行 worker 的 Python 解释器内，避免错把 Windows venv 启动器的低内存当引擎峰值。

环境：Windows 11 x64，Intel Core 5 210H、12 个逻辑处理器、约 16 GiB 内存，Node 26.13.0、Python 3.14.3。硬件记录不包含账户、机器序列号或密钥。详见 [硬件](../artifacts/code-data-phase6/hardware.json)、[数据规模实测](../artifacts/code-data-phase6/data-performance/performance.json)。

已扫描源码、构建、文档、产物和用户状态中的已知保存凭据，未打印密钥，也没有读取 Desktop key.txt。初次扫描 8,381 个文件；加入实网产物后扫描 9,383 个文件；脱敏优化并重新构建后扫描 9,564 个文件，均未匹配到已知凭据明文。npm 审计为 0 条已知漏洞；5 个固定 Python 包通过 OSV 查询未返回已知记录。该结论有查询时间和范围，不表示不存在未知漏洞。见 [优化后的凭据扫描](../artifacts/code-data-phase6/security-optimized/security.json)、[npm 审计](../artifacts/code-data-phase6/security-optimized/npm-audit.json)、[Python OSV 查询](../artifacts/code-data-phase6/security/python-osv.json)。

## 运行与限制

保持本机调试方式；没有打安装包或发布。已确认全局 `emergence` 入口的目录链接指向 `M:\涌现TUI\emergence`，`--version` 正常返回；关闭旧进程后重新启动即可使用本轮构建。第四阶段的远程数据库专用适配仍未配置或实测。MCP 验收覆盖真实本机协议 fixture，不表示所有第三方远程服务都可用。数据方法仍遵守第五阶段的统计前提、数值与输入上限。
