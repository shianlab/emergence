# 2026-11-16 全盘巡检与开源准备

## 结论与范围

当前版本完成了源码静态检查、关键执行及安全链路审查、修复后的回归、真实 Windows 终端检查、原生配置窗口操作，以及干净源码副本的安装、构建和测试。在本次已验证范围内，没有留下阻止本机使用和准备源码预览版的已知失败项。

产品范围以最新决定为准：保留多个独立窗口，由用户分别布置任务；不恢复主窗口控制和跨窗口派发。KIM、单会话 Harness、工具、子代理、Skills、MCP、记忆、权限、代码和数据能力继续保留。历史编排夹具用于验证共享引擎的状态、审批和恢复契约，不代表产品重新提供协作模式。

这不是“所有代码永远无 bug”或“所有平台已认证”的结论。当前主要验证 Windows x64、Node 26.13.0、PowerShell/Windows Terminal，数据环境为 CPython 3.14 x64。尚未执行 GitHub 云端 CI、全新 Windows 用户/机器试用、付费供应商在线组合验收和整日运行测试。

本轮没有上传 GitHub、发布 npm、创建远程仓库或提交本地 Git。已有未提交开发内容被保留。用户选择的自有代码许可证已落实为 MIT。

## 架构与代码维护

对当前 TS/Python 源文件生成静态导入图：156 个源文件、28,062 行、855 条静态导入，`core → app` 反向依赖为 0；静态运行时图没有环。检查范围不包含动态计算导入和运行时事件连线，相关关键路径另行阅读。

现有分层可继续维护：`core/domain` 管规则和契约，`core/application` 经端口组织流程，`adapters/storage` 连接 Harness 与存储，`app` 管界面和组装，`domains/code/data` 管专业工具。没有为修复测试再增加第二套状态机、执行器或重试队列。

仍需明确保留的维护债务：

1. `workspace-ui.ts` 约 1,670 行、`controller.ts` 约 1,164 行、`planning-service.ts` 约 1,102 行，职责较多。后续应分别按输入/导航/布局、回合生命周期/审批、计划验证/证据整理拆分，每次保持契约和行为回归；本次没有为了缩短文件而机械搬移或大面积改写。
2. 退役跨窗口功能的一部分共享引擎和历史测试仍存在，用于持久化兼容、任务证据和单会话执行。公开入口已关闭；进一步裁剪必须先列出真实调用和数据兼容关系，不能按 `team/master` 关键字直接删文件。
3. TypeScript 已有统一格式与架构门禁；C# 和 Python 通过构建/执行及专项回归。本次没有宣称这两种语言已经具备与 TS 同等的全量格式门禁。它们的格式规范可在独立整理中补齐，避免把大量纯排版改动混进安全修复。

以上是后续可规划的结构优化，不是本轮仍在失败的功能。项目还不能承诺零维护债务，但已有明确层次与可持续执行的门禁。
