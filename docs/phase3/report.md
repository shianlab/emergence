# 第三阶段交付报告

版本：0.0.3-phase3。日期：2026-10-29。

## 已交付

正式 `emergence` 已从单窗格升级为多窗口独立工作台。窗口可绑定同一或不同项目、同一或不同模型，分别接收用户指令。左右/上下分屏、鼠标和键盘调宽、焦点切换、最大化及窄屏折叠均已接入实际 Harness 会话。

- 每个窗口持有独立 SessionController、草稿、滚动位置、工具状态、审批和问卷。输入按提交时的窗口身份路由。
- 隐藏窗口保持任务执行，通过 `/panes` 与 `/show` 找回；`/terminate` 单独停止并释放会话。Esc 只停止焦点窗口，退出应用停止全部会话。
- 布局与会话关联按启动项目保存，持续流式输出时也定期落盘。重启恢复历史、项目、模型、草稿与滚动位置，不自动重放未完成任务。编辑选区保留于本次运行的切换和隐藏/还原，重启不恢复选区。
- 目录、模型配置或会话失效时保留错误窗口；可 `/retry`、`/model <有效配置>` 或 `/project "目录"` 修复。损坏布局明确报错，使用 `--fresh` 重建，磁盘历史保留。
- 同项目窗口显示共享提醒；自身 `write/edit` 的重叠同文件修改会在工具分派前拒绝第二个执行者。可用 `/worktree "新目录"` 创建独立 Git 工作树并打开窗口。
- 当前最多托管 16 个窗口，实际重点验收 2/4 个窗口。主控派活留在第四阶段。

## 架构

新增布局树模块、WorkspaceController 和独立工作台 UI。窗口管理与会话运行分开：布局树只保存可见窗口，隐藏窗口仍在会话集合中；分屏与恢复创建实际 AgentHandle，调整布局不重建编辑器或取消会话。

窗口恢复、项目替换和释放有生命周期检查，同一会话不能被两个窗口同时恢复绑定。退出会等待正在创建/替换的会话收尾，持久化采用临时文件加原子替换。共享文件保护按实际项目目录解析并规范化路径，覆盖已有路径及尚未创建的子目录。

实现位置：[布局树](../../emergence/src/app/layout.ts)、[工作台管理](../../emergence/src/app/workspace.ts)、[终端界面](../../emergence/src/app/workspace-ui.ts)。

## 验证边界

本阶段没有重复发起收费请求。DeepSeek 官方真实回复、文件读写与跨进程恢复沿用 [第二阶段实网证据](../../artifacts/phase2/live-deepseek.json)；多窗格并行验收采用本地模型测试服务，另一家真实供应商仍待凭据和实网验收。

共享提示和工具保护不能防止 shell、MCP、外部编辑器或先后发生的过期内容覆盖；worktree 创建 detached HEAD，停止窗口后保留目录，不自动合并成果。多终端同时打开同一工作台、长时间压力测试、异常断电恢复和完整终端兼容验收仍属于后续稳定性范围。

ConPTY 不覆盖物理中文输入法候选框、系统剪贴板 UI 和字体人工检查。测试驱动在确认应用与 shell 退出并完成落盘后显式结束，以绕过 node-pty 的 Windows conout worker 保留；这不代表全部测试资源自然回收，Harness 释放另由 Registry 清空探针验证。

## 使用

直接输入 `emergence`。F2 左右分屏、F3 上下分屏，Tab 切换，F7 最大化/还原，F8 隐藏。指定项目与模型可以输入：

```text
/split right "M:\另一个项目" deepseek
/panes
/show 1
```

详细操作与持久化位置见 [应用 README](../../emergence/README.md)。
