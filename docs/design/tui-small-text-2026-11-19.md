# 辅助信息小字号正式接入

2026-11-19，用户在实际 Windows Terminal 的 A/B 预览中确认 B 版符合字号区分要求，随后授权接入。

## 显示规则

- 正文、回答标题、会话标题、输入、错误、审批和展开详情继续使用原生文字。
- 模型说明、普通回执、收起的共享项目摘要、目录与 Tokens 使用确认的较小字号。
- 沿用预览参数：字体像素数为字符行高 × 0.8 × 0.875；这是视觉估算，不是终端实际字体字面高度的精确比例。仍占一行，不虚构更小行高。
- 小字由 Windows 字体系统生成，通过 OpenTUI Sixel/Kitty 显示。图形部分不能像普通文字那样选择复制。无图形协议、绘制失败、NO_COLOR、TERM=dumb 时回退原生文本；`EMERGENCE_NATIVE_TEXT=1` 可主动恢复可复制文本。
- 首页书法标识及 Agent 执行逻辑不变。

## 实现与资源

`SmallText` 将普通文字与图像放在同一布局位置。文字或尺寸改变时立即恢复原生文本，当前版本图像准备好后才切换，防止显示旧目录或旧 Tokens。错误与确认提示不等待绘图。

每个工作台只有一个按需启动的隐藏 PowerShell 字体进程，通过 JSON 标准输入输出传递已脱敏内容及 PNG。不在磁盘写用户辅助文字或临时图像。绘制请求串行，合并同帧相同内容，缓存上限 128 项且不超过 8 MiB。进程失败或超时回退原生文字；关闭工作台结束进程，关闭窗格释放对应图像。复用既有 frame 驱动，没有新增周期轮询。

构建复制字体脚本至 `dist/small-text.ps1`，发行打包纳入完整性清单。源码与本机安装使用不同目录，本次另制本地候选，通过现有安装管理器验证并切换，不直接覆盖运行中的安装文件。

## 用户截图反馈后的修复

用户实际截图显示重复模型行、顶部遮挡及底栏丢失。此前只核对小字图像加载与无图形字符帧，未覆盖 Sixel 在终端底边的整屏呈现；“图片加载成功”不能代表视觉验收通过。

已发现的风险是最后一行的 Sixel 绘制：图像按六像素一带编码，末带及光标落点可能超过终端底边并触发滚屏，导致 OpenTUI 保存的字符画面与实际终端错位。Microsoft 的 [SixelParser 实现](https://github.com/microsoft/terminal/blob/main/src/terminal/adapter/SixelParser.cpp) 包含相应的文本缓冲区滚动逻辑。这与截图中的残留现象一致；没有把推断描述成已录屏复现。

修正内容：

- 页面底部保留一行空白；小字服务检查 Sixel 的末带及光标空间，不安全时使用原生文字。
- 缩放事件到达时立即隐藏旧小字图像，在新布局确定后恢复，避免只在绘制完成后检查。
- 窗口顶部的模型行只放供应商/模型，不再追加目录；完整目录仅在全局或各窗口底栏出现。模型回复正文由模型生成，不擅自过滤其中的目录文字。
- 单会话隐藏重复导航栏；多会话导航只放编号、会话及状态，不重复项目名称。

新增 `tests/tui-small-text-layout.ts`：真实字体栅格和原生图像组件、强制 Sixel 能力投影，8 组单窗/上下分屏/缩放组合，在呈现之前检查每张图像边界，保证输入区与底栏不重叠。`tui-small-text.ts` 增加最后一行回退、保留空行恢复和缩小窗口回退；`tui-phase4.ts` 增加模型只显示一次、目录只在底栏、单会话不重复导航断言。另有 32 组原有布局矩阵、类型/格式/架构检查通过。上述检查不等于真实 Windows Terminal 整屏截图验收。

本机修复候选为 `1.0.5-local.3`，证据文件以 `fix-` 开头，保留此前记录，便于追溯这次漏测。
