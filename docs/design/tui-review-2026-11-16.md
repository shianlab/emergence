# 2026-11-16 整体巡检

本轮在 Windows 本机检查当前独立窗口版本，包括代码规范、构建、核心与 Harness 集成、原生 OpenTUI、ConPTY 终端、模型配置路由、恢复机制和已知凭据泄漏。下列实际执行的检查均通过，未发现阻塞当前 TUI 使用的问题。没有调用付费外部模型。

## 发现与修复

1. **任务详情残留旧角色文案。** 独立窗口已经取消主窗口控制，任务归属与会话标识仍写“主控”。改为“发起会话 / 执行会话”，空列表改为“暂无任务”。原生任务详情回归增加了旧文案排除断言。
2. **工作区验收仍调用退役功能。** 原生测试还在设置主控，终端测试还在派发跨窗任务，导致测试失败。原生回归改用独立窗口并继续检查任务详情、草稿、选区、滚动、后台确认与窄屏；ConPTY 回归改为真实 CLI 的独立项目/模型、分屏、切换、缩放、关闭和退出检查。
3. **模型配置运行验收预期过时。** 旧用例仍依赖主/副窗口的默认模型分配。改为新窗口默认模型与窗口编号覆盖，验证独立窗口角色；原有模型热切换、会话历史、DPAPI 密钥轮换、跨进程读取与协议检查继续保留并通过。
4. **故障测试与当前重试策略不一致。** 旧断言要求网络故障只请求一次。按当前有限重试策略检查初次请求加两次重试，并继续验证失败退出、密钥脱敏、写入只执行一次和恢复不重放。另跑 HTTP 恢复验收核实重试事件与实际请求次数。
5. **10 个排版相关文件格式不一致。** 已按项目 Prettier 配置整理，最终格式检查无失败项。

产品代码只调整任务详情文案及格式；保留其他窗口的编排、独立窗口迁移等已有修改。首页书法标识、聚合标记、既定配色和字号策略未变。

## 范围与限制

- 这是上述项目的实测结果，不等于所有历史阶段脚本均已通过。`inspect:full` 还包含旧跨窗协同/团队 UI 验收（如 `phase4-terminal`、`experience-e4-terminal`）；它们需要随退役功能另行整理，本轮未将其算作通过。
- 模型请求均使用本地受控服务或 Harness 测试适配器；未验证外部供应商当时的可用性与计费。
- 原生 TUI 检查使用实际渲染器与 ConPTY 数据，不冒充 Windows Terminal 的人工截图验收。本轮未再次打开 WinForms 窗口做逐控件人工验收。
- 密钥扫描识别的是本机已保存的已知凭据；不能据此宣称不存在所有未知秘密或安全问题。依赖审计结果以本次查询为准。
- 仓库存在其他工作的未提交改动，本轮未回滚、提交或清理这些文件；保留日志作为证据。
