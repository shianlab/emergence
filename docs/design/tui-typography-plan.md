# TUI 文字层级优化方案（待确认）

日期：2026-11-16。范围：文字呈现、提示区域及阅读层级；本轮仅规划，不修改正式界面。

## 现状

- `workspace-ui.ts` 的 renderNotice 将普通回执、全局消息和共享项目提醒合并输出，普通信息与重要提示缺少明确区分。
- `rich-text.ts` 的 heading 分支统一采用加粗，没有区分 Markdown 标题深度。
- 普通文字由终端字符网格渲染，当前 TextRenderable 没有通用的逐元素 fontSize 设置。
- 2026-10-31 留存的本机检测记录为 scaled_text=false、sixel=true。这是历史回执，第一阶段需复测，不能当作当前能力的保证。图片协议与局部文字缩放是不同能力。

## 目标层级

正文与输入保持舒适的基准大小。会话标题和回答内章节通过字重、前后空行、分组建立主次；辅助信息以正文约 85%–90% 字号作为试验目标，前提是终端支持且清晰可读。比例是设计目标，不是已经支持的配置项。

| 层级 | 内容 | 呈现原则 |
| --- | --- | --- |
| 主要阅读 | 用户问题、助手正文、输入内容 | 基准大小、正文对比度、稳定段落间隔 |
| 内容组织 | 会话标题、回答内章节、发言人 | 字重和空间分组；可行时少量字号差异，避免大标题挤占内容 |
| 辅助信息 | 已提交、普通完成回执、共享项目计数、模型、目录、Tokens、消息序号 | 小字试验、紧凑单行、取消无意义加粗；不只降低亮度 |
| 必须处理 | 操作确认、错误、真实文件冲突 | 保持正文大小与可读性，不能随辅助信息一起缩小或自动消失 |

## 第一阶段：字号可行性与原生样张

复测当前终端文字缩放和图形能力。使用同一段中文和实际布局制作原生样张：A 为标准文字排版改善；B 为辅助小字效果。B 优先验证文字缩放协议；若不支持，仅试验少量非交互辅助标签的图形文字，不将正文或输入框图片化。

验收：中文清晰度、基线、实际占用行数、窗口缩放、重绘残影、选择复制和可访问性。图形文字可能不支持普通文本选择/屏幕阅读，不能仅因外观相似直接推广。明确展示样张使用的渲染方式和限制；用户选择后再接入。若 B 不合格，说明当前终端限制并采用 A，不用网页效果冒充终端实现。

## 第二阶段：辅助信息区减重

优先处理用户点名的已提交和共享项目提醒：普通提交回执短暂出现，由真实运行状态接替，避免多行状态堆叠；普通共享项目提示收为简短的“共享项目 · N 个其他会话”，完整说明按需展开。真实冲突警告持续可见。

底栏继续只放目录和实际 Tokens。统一辅助文字的大小（若第一阶段验证可用）、字重、位置和间距。错误、确认、排队和运行状态按各自实际含义处理，不借视觉简化隐去任务状态。

验收：输入区上方不重复叠放成功回执与就绪提示；每个会话保留自身状态和 Token 归属；重要提示不被折叠规则误伤。

## 第三阶段：对话与章节层级

统一用户/助手发言人、回答章节、正文、工具摘要、引用与消息序号的样式。Markdown 一级、二级、三级标题通过段前段后留白、字重、缩进等建立不同层级。主要正文和代码保持可选择复制的原生文本。引用与工具详情保持足够对比度。

验收：长回答能快速找到章节；正文仍是主要阅读内容；列表、代码、表格不因排版改变丢失内容或错位。

## 第四阶段：全局适配与收口

检查单窗、分屏、窄屏、不同终端字体/缩放、明暗主题与无色模式。新增样式集中为语义层级配置，避免每处单独调整。若使用图形辅助字，检查协议切换、资源释放、刷新成本及不支持时的原生文字回退。

交付：真实终端前后对照、已支持与回退行为说明、针对改动的回归记录。每阶段独立验收，不扩大 Agent 编排工作范围。
