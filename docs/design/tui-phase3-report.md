# 涌现 TUI 第三阶段记录

日期：2026-10-30。范围：输入区、命令选择、操作指引与运行反馈。保留已确认的白灰 Logo、首页布局和第二阶段消息排版；第四阶段的多窗格视觉打磨未提前开展。

## 正式实现

- 输入区根据 OpenTUI 原生编辑器的实际折行增长，常规尺寸默认 3 行、最多 7 行；小窗格默认 2 行并降低上限，超出后在编辑区内滚动。首页只使用现有布局的剩余高度，空首页的位置和 Logo 不变。确认回答编辑器上限为 5 行。
- 中文、emoji、换行、缩进和普通任务的首尾空白保留。粘贴不会自行提交；Enter 发送，Shift+Enter 换行。命令解析仍去掉命令外侧空白。
- `/` 提供命令候选，Ctrl+P 提供独立搜索框，可按命令名或说明筛选；支持方向键、Enter、Esc 和鼠标。精确命令和名称前缀优先于描述中的匹配。需要参数的条目补全后继续编辑；不从候选中伪造参数。
- 候选来自实际实现的命令及扩展当前注册表；运行、确认和会话不可用时过滤部分不适用操作。完整命令仍由现有控制器校验。等待确认时，独立命令入口保留帮助、权限、焦点切换和退出等入口，其他输入不能误变成确认回答。
- 输入区上方显示就绪、正在运行/输出、实际执行工具、排队条数、等待回答和停止中的状态。工具名及参数摘要来自 `tools/execute` 的作用域与生命周期；排队条数只统计当前 Agent `inbox.nextTurn` 中尚未处理的用户输入，不把运行上下文算作排队任务。
- 底部指引按运行、确认、命令选择、参数编辑和信息面板切换。停止、切换、分屏、权限键从实际配置生成。上下文容量继续标作配置容量，不生成虚构使用比例或费用。
- 命令与聊天草稿使用不同编辑器；取消命令选择保留聊天草稿和选区。发送失败后恢复完整草稿、光标和选区，若用户已经开始新草稿则不覆盖。独立命令失败后保留命令供修改。
- 长信息面板从顶部打开，关闭后恢复对话阅读位置。停止仍调用既有取消入口，保留原有取消队列、审批归属及 Ctrl+C 分层行为。

## 与并行窗口的兼容

本轮工作期间，并行窗口新增了模型、历史、角色和任务选择器，复用了命令列表。保留其导航、派发、权限、任务验收与历史回填逻辑；第三阶段负责输入布局、筛选组件和上下文提示，不改写编排策略。

## 查看与复现

重新运行 `emergence` 即可使用正式实现。脚本 `test:tui-composer` 与 `test:tui-composer:terminal` 分别运行原生及 ConPTY 专项，使用项目要求的 Node 26。

`probes/composer-preview.ts` 从实际工作台组件导出多行输入、命令筛选、运行与排队三种示例帧至 `artifacts/brand/composer-preview.html`。页面按钮只切换静态终端帧；正式输入与命令操作在真实 TUI 中使用。
