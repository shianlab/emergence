# 涌现 TUI 第四阶段记录

日期：2026-10-30。范围：多窗格视觉组织、会话导航、任务详情和窄屏适配。四个 TUI 阶段现均已实施；保持已确认的白灰 Logo、首页、Markdown 排版和输入行为。

## 正式界面

- 顶部品牌与运行统计分层显示，下一行是可点击的会话导航。导航使用窗口编号、项目短名和主控/执行/接管角色，当前窗口通过标记、字重和灰色底区分；待确认显示 `◇`，运行显示 `●`。用户点击后台窗口时调用既有显示/焦点入口。
- 会话多于一行能容纳的数量时，围绕当前焦点显示一组入口，保留省略数量。编号仅用于显示，点击与控制器操作仍使用稳定 pane ID。Tab 与原有窗口命令继续可用。
- 单会话移除包围整个内容区的边框，保留左右留白；分屏采用浅灰焦点边界和较暗的非焦点边界。标题突出角色和状态，下一行集中显示模型与目录，长目录按实际终端列宽保留尾部。
- 右上角「任务」打开全局任务面板。原 `/tasks`、F4 和模型/历史/角色选择器保留；从任务选择器进入详情，或使用 `/task show <ID>`，打开结构化任务详情。
- 任务面板展示状态计数、任务列表和独立可滚动详情。目标、最新回执、归属、失败回执、验收证据、验收标准、结果、交付物、目录/模型配置、依赖、预算和日志各成一组。字段标题用字重区分，任务与工具原文按普通文字展示。
- 状态直接读取 `TaskRecord.status`。只有 `succeeded` 显示已完成；待检查、等待用户、阻塞、取消和中断分别标明。执行者自报与运行时结果、主控验收分开，不从输出文案或成功自报推断任务成功。

## 宽窄屏与操作

| 场景 | 行为 |
| --- | --- |
| ≥118 列打开任务详情 | 右侧 38–54 列任务侧栏，其余空间按现有布局显示会话 |
| <118 列打开任务详情 | 内容区切到任务页，返回后恢复原焦点窗口和输入状态 |
| 分屏空间不足 | 沿用现有焦点窗格折叠规则，不改写保存的分屏树 |
| ↑↓ | 在任务面板中选择任务，选择 ID 在状态刷新时保持 |
| PageUp/PageDown | 滚动任务详情，遵循实际自定义绑定 |
| Enter / 进入执行窗口 | 校验任务原 targetSession，调用既有任务焦点命令 |
| Esc / 关闭 | 返回会话；关闭详情不取消任务、不回答确认 |

原执行会话已被替换或关闭时，任务仍可阅读，但不能借旧任务跳到一个新会话。查看任务不请求模型，不执行任务操作；面板获得键盘焦点时，粘贴和普通按键不会进入隐藏的聊天框或确认组件。

宽屏可点击会话内容继续编辑，侧栏保留；明确打开命令/历史/任务选择时按当前操作切换。后台输出、状态变化和确认不抢走当前会话焦点。每个窗格的草稿、原生选区、滚动位置和绑定分别保留，缩窄、返回与恢复分屏不重建会话。

## 与编排工作的边界

新增 `workspace-chrome.ts` 和 `task-inspector.ts` 为展示模块。控制器仅增加可选 `task-inspect` 事件；无交互视图时 `/task show` 继续使用原文本详情。保留并行窗口的角色、任务验收/修复、权限、预算与导航选择器。任务详情的模型配置 ID 来自任务记录，不假称能还原一个已变更配置的历史供应商路由。

Logo 生成脚本、母版和已确认像素轮廓均未修改。深浅主题沿用用户的现有语义色；默认仍是黑白灰。
