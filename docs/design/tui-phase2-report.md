# 涌现 TUI 第二阶段记录

日期：2026-10-29。范围：消息分型、Markdown 阅读体验、工具摘要/详情、原文访问与流式阅读。第一阶段品牌保持定稿，第三、第四阶段没有提前实施。

## 正式对话页

- 消息按 Harness 的结构化事件投影为用户、助手、上下文、工具；使用会话 ID 和事件序号识别消息，用 callId 配对工具调用与结果，不从中文输出字符串猜角色或状态。
- 助手正文显示标题、加粗、斜体、有序/无序列表、引用、行内代码、代码块和表格。窄屏表格改为字段逐项显示，长列表续行保留缩进。HTTP(S) 链接附带终端链接数据；文件路径保留文字，不假装已注册文件打开能力。
- 用户内容、工具参数和输出按原文展示，不套 Markdown。工具成功显示摘要并可展开，失败详情默认展开；尚无结果的调用写「等待结果」，不猜测完成或取消状态。退出码仅在结果的结构化元数据提供时显示。
- 项目指引和运行上下文分开折叠，避免系统上下文淹没对话。助手有「原文 / 排版」入口，工具和上下文有展开/收起入口。
- 流式更新保留稳定前缀块，只重建变化的尾部；未闭合代码块即时显示内容。正在向上阅读时保留滚动位置和草稿，显示新内容/回到最新提示。新确认请求临时露出完整详情，取消后恢复阅读位置；它不改变其他会话的焦点。

## 操作

点击消息旁的入口，或通过聊天框/Ctrl+P 输入：

| 命令 | 行为 |
| --- | --- |
| `/view raw [序号]` | 最近一条或指定助手消息的 Markdown 原文 |
| `/view render [序号]` | 恢复排版 |
| `/view tools [序号]` | 展开或收起工具详情 |
| `/view more [序号]` | 继续显示长内容 |
| `/view latest` | 回到最新，不覆盖草稿 |

消息标题中的 `#序号` 对应会话事件序号；命令仅改变当前窗格展示，不请求模型、不执行工具。完整 JSONL 历史不变，原来的 `transcript()`、`--print` 输出仍可用于自动化和导出。

## 实现与边界

`message-model.ts` 维护最多 200 个可见消息项的增量投影，完整历史由 Harness 保留。每条内容默认先展示 16000 字符，可以继续展开；更早记录显示导出完整历史的提示。不能把界面暂未展示的部分当作已经从会话中删除。

`rich-text.ts` 使用已安装的 Marked 17.0.1 与 OpenTUI 0.7.0 的 Markdown 块复用，正文与代码同步渲染。代码高亮只用有限的灰阶、字重和底色，不依赖外部解析器下载，不修改代码字面量。HTML 保持终端文字；字符引用不会重新引入终端控制码。高级 Markdown 扩展和 IDE 级语法高亮不在本阶段承诺中。

`message-view.ts` 管理每条消息的原文、折叠与展开量；`workspace-ui.ts` 继续管理现有窗格、编辑器、确认组件和生命周期。并行窗口新增的权限、指引和交互行为继续保留。
