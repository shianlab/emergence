# 涌现 TUI 界面优化方案

日期：2026-10-29。范围：启动界面、消息呈现、输入与操作提示、多会话的视觉组织。Agent 编排、任务调度和执行策略由另一工作窗口负责，本方案定义它们在界面中的呈现与数据接口。

设计状态：四个阶段均已按用户指令接入正式 TUI。首页和品牌保持定稿，消息、输入反馈及多会话/任务展示分别见 [第一阶段记录](tui-phase1-report.md)、[第二阶段记录](tui-phase2-report.md)、[第三阶段记录](tui-phase3-report.md)和[第四阶段记录](tui-phase4-report.md)。此前的绿色主界面方案不再作为实施依据。

## 设计结论

采用「启动时建立品牌与运行上下文，对话时突出内容，操作始终在底部」的结构。保留用户手写的魏碑像素 Logo，Logo 采用白灰层次；界面以近黑、深灰和灰白组织层级。界面首先说明当前项目、实际模型和运行状态，然后让用户开始输入。

模型回复继续使用 Markdown 作为内容格式，界面将它渲染为有层级的终端排版。用户消息、助手正文、工具执行和待确认操作分别显示，保留完整历史和原文。

## 当前工程的问题

| 现状 | 影响 | 优化方式 |
| --- | --- | --- |
| `workspace-ui.ts` 启动后直接挂载窗格；顶部只有两行字符串 | 品牌、项目与模型信息缺少主次 | 增加独立首页，首次提交后进入对话页并收起大 Logo |
| `controller.ts` 的 `eventLine()` 将不同事件转成字符串；视图再将其拼接到同一 TextRenderable | 标题、粗体、代码、工具参数混在一起 | 增加按事件类型组织的消息视图模型，分别渲染 |
| 模型标题主要显示配置 ID | 自定义别名不能清楚说明实际模型 | 显示供应商 / 实际模型，配置别名作为次级信息 |
| 底部固定展示分屏、切换、任务、关闭等一长串操作 | 发送、换行和当前可执行动作不突出 | 区分输入提示与工作台状态，按状态切换操作提示 |
| 现有 dark 主题仍是深蓝与青色 | 与已确认品牌方向不一致 | 通过主题语义字段统一替换，移除组件内散落色值 |

## 借鉴 Claude Code 与 OpenCode 的内容

| 参考 | 已核对的行为 | 涌现中的应用 |
| --- | --- | --- |
| Claude Code 的全屏交互 | 输入区固定；可展开工具详情；用户向上阅读时暂停自动跟随 | 输入区保持稳定，工具先给摘要，阅读历史时显示「回到最新」 |
| Claude Code 状态行 | 将模型、目录、Git、上下文等会话信息集中呈现 | 状态行简短显示当前焦点会话的信息，详细信息按需打开 |
| OpenCode 的 Home / Session 分离 | Home 组织 Logo 与输入入口；Session 将消息正文和工具呈现分开 | 建立欢迎态与工作态，避免大 Logo 长期占用对话空间 |
| OpenCode 的消息组件与 TUI 配置 | 使用 Markdown 组件；支持工具详情、主题和快捷键设置 | 优先使用已有 OpenTUI 能力；快捷键继续遵循涌现现有定义 |

这些是交互组织上的借鉴；涌现采用自己的书法品牌与多会话结构。

## 视觉规范

- 美学方向：克制的等宽编辑排版，适合长时间阅读的黑白灰终端工作台。
- 近黑背景 `#111111`；深灰表面 `#181818`；灰白正文 `#dedede`；浅灰强调 `#e5e5e5`；中性分隔线 `#303030`。
- 次级文字使用有足够对比度的中灰 `#a3a3a3`。成功、失败和待确认同时使用文字、符号与字重，不只依赖明暗。错误与长输出不能被默认折叠后隐藏。
- 字体遵循终端设置。原型使用 Consolas，中文优先使用等距更纱黑体 SC；实际 TUI 不强制修改用户字体。
- 终端内字号保持一致。层级主要通过粗体、颜色、空行、缩进与细分隔线建立，不依赖网页的大字号、圆角或阴影。
- 品牌母版与色值入口：`emergence/assets/brand/yongxian-wordmark.png`、`design-tokens.json`。绿色参考图仅作历史素材保留。

## 启动界面

根据用户最新调整，所有尺寸都采用上方居中的品牌标识：缩小的手写像素「涌现」下接像素英文 `EMERGENCE`，运行信息统一放在标识下方。中央输入区最多 88 列，与标识同轴。信息按以下优先级组织：

1. 涌现 / Emergence 与版本。
2. 实际供应商与模型，例如 DeepSeek / deepseek-flash。
3. 当前项目目录；检测到 Git 仓库时显示分支。
4. 独立或协作模式，以及当前会话角色。
5. Skill / MCP 的已加载数量、失败状态；详细列表通过已有命令查看。

下方是主要输入区，并提供少量入口：继续上次会话、选择模型、帮助。入口执行现有命令，不创建另一套业务逻辑。

### 首页与会话页的切换

普通输入 `emergence` 必须先进入独立首页。用户提交第一条任务后，才创建或绑定目标会话并进入对话页；第一条输入原样成为该会话的用户消息。首页不是带空消息列表的对话窗口，也不是一闪而过的启动画面。

首页保留「继续上次会话」入口；用户明确选择历史会话，或使用显式 `--resume` 时，进入对应历史。已有布局快照仍保留供继续工作台使用，不因本次进入首页而覆盖。首页空闲时不产生用户轮次或工具执行，动画不阻断输入；发送按钮与 Enter 共用一次提交路径，防止重复创建会话。

### Logo 与终端宽度

新增的首页标识直接从原始透明母版按原阈值采样，不改变书法字形；通过象限块将每个字符的横向采样翻倍，在相同占屏尺寸保留更多轮廓细节。原 96/72 列版本作为素材保留，首页使用更小的版本。英文固定为 38 列 × 3 行；中英文之间空一行，运行信息再下移一行。输入框、框外模型状态、快捷键、入口和退出提示分别成组，常规终端高度下组间留一行。

| 终端空间 | 欢迎区 |
| --- | --- |
| ≥60 列、≥32 行 | 56 列 × 11 行中文标识，下接英文和运行信息，38 行以上顶部留两行，其余留一行 |
| ≥50 列、≥28 行 | 48 列 × 10 行中文标识，下接英文和运行信息，顶部留一行 |
| ≥42 列、≥24 行 | 40 列 × 8 行中文标识，下接英文和供应商/模型、项目两行核心信息 |
| 更窄或更矮 | 使用紧凑文字品牌，优先保留模型、输入与必要操作 |

启动动画使用白灰明暗层次，约 1–1.5 秒轻缓显现。用户开始输入即可结束动画，不等待固定播放时间。正常启动后保持静止；显式恢复历史会话时直接进入工作态。`--print`、帮助、版本和管道输出不播放动画。

## 对话界面与 Markdown 呈现

开始对话后，欢迎区收起。顶部仅保留品牌、当前项目、会话导航与当前模型。主体空间交给消息，输入固定在底部。

| 内容 | 呈现规则 |
| --- | --- |
| 用户消息 | 显示「你」与一段有轻微背景区分的正文；消息内原文保持可复制 |
| 助手正文 | 常规雾白文字；宽屏保留可读的段落宽度；段落之间一行空白 |
| 标题 | 使用粗体和空行，隐藏格式用的 `#`；避免每个标题都画框 |
| 粗体 / 强调 | 以终端粗体或强调色表现，格式用的星号不直接出现 |
| 有序与无序列表 | 保留编号、统一缩进；续行与正文起始位置对齐 |
| 行内代码 / 文件路径 | 使用等宽文本与轻微底色；支持时提供可点击的文件定位链接 |
| 代码块 | 独立区块、语言标签、有限的语法高亮；长行允许换行或专门展开 |
| 表格 | 按内容分配列宽；窄屏改为逐项字段展示，保持字段对应关系 |
| 引用 / 提醒 | 细竖线和次级文字；重要提醒增加文字标签 |
| Diff | 保留 `+` / `-` 和文件路径，不能只靠颜色区分 |
| 工具执行 | 显示工具名、动作摘要和状态；展开后查看参数、输出、错误与退出码 |
| 待确认操作 | 独立展示命令、目录、影响与明确选择；始终标明所属会话 |

正文提供「查看原文」入口，方便复制或排查格式。命令输出、路径、参数 JSON 和用户原文不能未经区分地当成 Markdown 解析。

流式输出只更新当前消息的末尾区块。未闭合代码块、列表和表格需要稳定的临时布局；完成后再结算样式。用户向上滚动后暂停自动跟随，显示新增消息数量与「回到最新」，不要抢走阅读位置。

## 输入区与下方指引

输入区由三部分组成：简短状态提示、可增长的编辑区域、上下文相关的操作提示。默认 2–3 行，多行输入增长到合理高度，超过后在编辑区域内滚动。

| 状态 | 主要提示 | 次级信息 |
| --- | --- | --- |
| 空闲 | Enter 发送 · Shift+Enter 换行 · / 命令 | 实际模型、项目、模式 |
| 正在运行 | Esc 停止当前会话 · Enter 排队 | 正在执行的真实工具摘要、排队数量 |
| 等待确认 | y 允许本次 · n 拒绝 · Esc 取消 | 所属会话、工作目录、完整命令 |
| 查看历史 | 回到最新 · 新消息数量 | 不覆盖输入草稿 |
| 命令选择 | 上下选择 · Enter 确认 · Esc 关闭 | 只列出当前确实可用的命令 |

Tab 继续用于切换窗格；F2 / F3 继续用于分屏；Ctrl+C 保持现有退出行为。借鉴外部产品的布局，不直接照搬会与现有操作冲突的键位。界面提示必须从用户实际配置的快捷键生成。

上下文使用量、费用、Git 分支、MCP 数量均来自真实数据；拿不到时显示「—」或省略。当前代码显示的 `contextWindow` 是配置容量，不能直接当成已用 token 或使用百分比。

## 多会话与编排界面的边界

默认单会话尽量减少边框。分屏后，每个窗格保留独立标题、消息、草稿、选区和滚动位置；焦点窗格使用清楚但克制的边界。全局底栏显示工作台操作，各窗格显示自己的运行与确认状态。

主控、执行者、排队和人工接管通过已有稳定 ID 与真实事件呈现。任务栏以任务 ID、归属会话、目标摘要、状态和结果入口为核心；不由界面字符串猜测任务完成，也不显示没有数据来源的进度百分比。窄屏仍采用现有的焦点窗格折叠规则。

UI 层需要的只读数据契约：

- 会话：稳定 ID、模型配置与实际模型、目录、角色、运行/待确认状态。
- 消息：稳定 ID、角色、内容块、流式状态、来源会话/任务、时间。
- 工具：调用 ID、工具名、参数、输出、退出码、失败/取消状态。
- 任务：任务 ID、主控/执行者会话 ID、目标、真实状态、明确结果引用。
- 操作：发送、取消、响应确认、焦点切换、分屏与查看任务，调用现有控制器入口。

新增展示字段时先明确数据来源，再接入编排侧提供的接口；UI 不改变调度与权限语义。

## 建议的工程组织

保留现有 CLI 和工作台控制器，在 `emergence/src/app/tui/` 中分离视图职责：

| 模块 | 责任 |
| --- | --- |
| `theme.ts` | 将品牌色映射为终端语义色，支持深浅与无彩色降级 |
| `home.ts` / `brand.ts` | 欢迎布局、Logo 尺寸选择与可中止动画 |
| `message-model.ts` | 从结构化会话事件投影消息，保留归属与稳定 ID |
| `message-view.ts` / `rich-text.ts` | 用户/助手/上下文分型与 Markdown 渲染 |
| `tool-view.ts` / `approval-view.ts` | 工具摘要、详情与所属会话确认 |
| `composer.ts` / `statusline.ts` | 输入状态、真实快捷键与运行信息 |
| `pane-view.ts` | 窗格焦点、滚动、草稿和布局复用 |

不从 `eventLine()` 的中文字符串反向识别事件类型。保留现有 `transcript()` 作为导出或兼容入口，新增 UI 投影；编排窗口正在修改控制器时，先落独立视图模块与固定事件样例。

## 实施顺序与验收

| 顺序 | 交付 | 验收重点 |
| --- | --- | --- |
| P0 品牌与基础布局 | 黑白灰主题、独立首页、靠上居中的中英文 Logo 与下方运行信息、提交后进入对话页、精简标题与底栏 | 普通启动先到首页；首次提交只创建/绑定一次会话；不丢失历史布局；80/120/160 列可用 |
| P1 消息可读性 | 按事件分型、标题/粗体/列表/代码/表格渲染、工具折叠 | 看不到正文格式标记；代码内容不被改写；流式末尾稳定；完整内容可追溯 |
| P2 输入与反馈 | 上下文操作提示、命令选择、运行/排队/待确认状态 | 中文输入、多行粘贴、停止、失败后草稿恢复、键位配置一致 |
| P3 多窗格与任务展示 | 主控/执行者视觉层级、任务详情与窄屏恢复 | 归属准确、不抢焦点、草稿/选区/滚动保持，任务状态只取真实事件 |

验收通过真实 Windows Terminal / PowerShell、VS Code 终端与项目现有无头/ConPTY 测试完成。重点覆盖中文双宽字符、长路径、长代码、长工具输出、持续流式更新、终端缩放、退出与光标恢复。

### 本轮交付与技术验证状态

设计交付包含启动工作台、结构化对话和多会话协作原型。四阶段正式实现已覆盖首页与品牌、消息排版、输入反馈和多会话/任务展示；第四阶段保留现有编排策略，以真实任务记录组织导航、焦点、结果与验收详情。

本地 OpenTUI 0.7.0 的 Markdown、流式块复用、自定义节点与表格已通过原生帧和 ConPTY 验证。段落、引用和代码使用同步自定义节点，避免异步语法高亮导致临时空白或依赖运行时解析器下载；代码保持逐字内容，采用有限的灰阶强调。流式测试验证已完成的前缀节点保持身份，读取历史时不跟随新输出。
