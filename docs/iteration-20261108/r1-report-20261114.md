## 代码职责

- native-evidence.ts：读取完整原生事件，按 session + call ID 建索引；拒绝重复身份、乱序与已完成但损坏的记录。仅忽略正在写入的末尾残行。
- acceptance-capture.ts：只读采集任务、原生日志、执行台账和测试文件哈希；排除助手思考和无关会话消息。旧数据只读，新重评独立保存。
- acceptance-oracle.ts：已知测试协议的统一判定入口，供真实验收与离线重放共同调用。依据命令参数和原生返回的实际 cwd 归属项目，不依赖“测试批准过哪些命令”。
- acceptance-diagnostics.ts：区分 planning、dispatch、execution、approval、verification、aggregation、transport，保留 task/run/session/call/approval 标识；未知错误仍保留原始原因，不一律归为网络故障。
- master-team-live.ts：接入同一判定器；结束后保存 acceptance-evidence.json、结构化 findings 和通过证据。模型运行终结失败时立即结束观察，随后仍执行原有进程清理。
- phase3e-live.ts：矩阵样本同时保存错误和分类 findings，不只保存 PASS/FAIL。
- assurance.ts：仅提取原有 subjectEvidenceVersion 纯函数，生产和重放共用同一版本计算；字段、排序算法与生产验收规则不变。

没有新建第二套调度器、审批许可或事实存储。此次新增代码主要是测试基础设施；测试不会给任意命令开权限，也不清除旧错误以制造成功。

## 拒绝错误证据的边界

验证同时核对原生调用/结果、宿主 receipt、命令执行台账、task/run/session/call、参数和结果哈希、精确命令、真实返回 cwd、退出码、独立审查身份、审查引用和当前产物版本。读取回执还要匹配原生文件路径；验证前须有独立的测试输入文件观察。

反向测试包括：脚本被篡改、产物字节改变、过期审查版本、旧 run、其他 task/session 回执、伪造结果哈希、缺少执行台账、非零退出码、原生工具失败、越过运行事件区间、旧读取版本、未引用验证命令、参数目录与实际目录冲突、其他会话的成功调用。均必须拒绝。

这仍是固定测试协议的判定器，不是任意项目的通用安全证明。Shell manifest 现有输入集合不足时，本轮使用宿主读取证据、已知脚本基线和隔离项目的最终字节共同核验；R2 再统一生产 VerificationSpec 和输入版本契约。离线采集文件哈希标注采集时间，不伪造历史时刻的文件快照。
