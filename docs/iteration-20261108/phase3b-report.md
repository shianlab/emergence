# 3B：主控分配与独立模式

日期：2026-11-12。基线：3A `f98fbb1`。本批处理匹配、窗口隔离、实时准入和幂等；不提前宣称 3C–3E 完成。

## 发现的问题与改动

1. 能力查询会跨越异步调用，旧代码可能混用查询前的团队状态和查询后的工具能力。新增运行期 v1 快照指纹，覆盖会话、项目、模型配置、权限与继承、角色配置、工具注册、偏好、接管、忙闲和队列负载。查询中有变化则丢弃派发能力；审批后重新查询实际可调用能力，事务提交前和保存结束时再次复核。
2. 旧的执行图互斥开始于审批之后，两次调用可能同时等待批准。现在同一请求同一执行图共享进行中的提交，其他图明确返回正在提交。执行身份不包含方案说明和分配理由等展示字段；普通用户消息与任务注入消息分开，子任务回流不会产生新的请求身份。历史旧键仍可识别，已存在的图返回原任务，不再次执行。
3. 旧代码逐项把批量任务放入公开列表，其他保存或已经启动的调度轮次可能观察到不完整图。现在先暂存整图，检查完毕后统一加入并保存；调度器在进入、异步返回和遍历时检查事务状态。保存失败或取消撤销本批任务；回滚存储也失败时暂停派发，报告需要核对存储，不继续运行新任务。
4. 匹配先检查项目、实际能力、模型和角色/权限，再处理忙闲及偏好排序。错误提供候选窗口、原因码和是否可等待，区分项目不匹配、缺能力、模型不可用、权限/角色不符、独立工作、接管和过期快照。路径越界在等待资源前拒绝。
5. 合适窗口正在独立工作或被接管时，主控可在本次计划调用内等待，显示具体原因，不先占用窗口或创建任务。解除条件满足后重新查询并匹配；等待可取消，受既有规划时长预算约束。每 500 ms 只重新核对本地能力，没有新增模型请求或第二个任务队列。
6. 选中的窗口在准入前变化时，自动主控可用已经验证的同一需求/工作分解重新匹配，计入原修订预算。权限拒绝和持久化故障不作为盲目重试理由。恢复入口对同一恢复决定共享审批和结果，重复请求返回已有恢复任务。
7. 巡检发现手工执行入口还可能绕过重复步骤 ID 检查。依赖图检查提取为领域层唯一实现，规划校验和执行准入共同使用；重复 ID、依赖环、缺失依赖在事务开始前拒绝。

## 结构与行为边界

- `allocation-snapshot.ts`：运行期观察版本；它不是权限授权，不改变历史任务绑定。
- `allocation-policy.ts`：规划与派发共用的角色、能力和权限资格检查。实际工具调用仍由原精确参数权限门禁判定。
- `dispatch-admission.ts`：执行图身份、实时复核与提交前检查。
- `work-allocation.ts`：候选过滤、负载/偏好排序和具体范围；不新增执行器。
- `Collaboration`、`TaskScheduler`、`TaskRecovery`：沿用原事务、队列、资源锁和恢复日志，只修正上述边界。

主控仍只协调其配置的团队。没有主控或协作未启用时，不自动征用其他窗口。忙碌的既有协作执行窗口可以排队；独立工作尚未结束的窗口不可被新任务占用。角色偏好只参与排序，不能代替真实工具、模型、权限资格。单步任务保留单步；依赖与同文件写入仍由现有调度及范围锁约束。

本批没有扩展模型工具菜单，沿用并回归首轮主控工具过滤、独立模式菜单恢复及 3A 的简洁引用式计划。没有修改正式 TUI 视觉或原生模型配置插件。
