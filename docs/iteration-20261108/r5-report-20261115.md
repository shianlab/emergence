## 本轮发现与修复

### Windows 状态快照写入中断

第一轮冒烟的业务闭环通过，但复核发现部分已经结束的运行，其磁盘计时快照仍为 running，请求数和阶段用时因此不完整。用相同 RunDiagnosticsStore 做并发读写，1,500 次写入中复现 130 次 EPERM（`diagnostics-concurrent-io.json`）。原子 rename 与 Windows 文件读取占用竞争；原实现把一次保存失败当作永久禁写，后续采样和退出保存都被跳过。

修复收敛在既有存储与计时模块：

- `safe-json-file.ts` 对 Windows rename 的 EPERM/EACCES/EBUSY 最多追加四次等待，依次 20/40/80/160 ms。每次重新校验目标，始终替换同一个临时文件；不原地覆盖、不删除目标，不重放调用方业务。
- `run-diagnostics.ts` 分开处理“原文件无法安全读取”和“本次写入失败”。前者继续保护原文件；后者保留内存计时及错误提示，后续正常采样/退出可再次保存，成功后清除写入错误。没有重置执行期限或请求预算。
- 验收脚本要求成功退出后的计时快照全部收敛，防止再次把不完整统计当作完整结果。

新增实测覆盖：并发读取、短期锁释放、长期锁明确失败且原文件完整、锁释放后最终快照恢复。针对性 10/10；完整回归 343/343，约 86.5 秒。持续占用超过有界等待仍会失败，这是明确的错误，不承诺无限等待。第一版高频无间隔压力测试失败日志保留于 `storage-targeted.log`；最终测试同时覆盖正常并发观察与确定性的长期占用。

### 跨项目验收器误判 Windows 目录大小写

修复后的跨项目冒烟在审批阶段被测试器提前中止：模型使用小写物理目录，测试器用区分大小写的字符串比较，与实际 Windows 项目身份不一致。不是命令落到另一个项目。原生调用和失败结果保留于 `fixed-smoke-cross/`。

`fixtureWorkdir` 现复用现有物理路径规范化，按所属任务目录解析相对路径，再与明确创建的测试项目逐一比较。补充大小写、斜杠、相对当前/兄弟目录、越界、子目录和非法路径检查；25 项相关路径与证据重放通过。没有扩大可批准的项目集合、Shell 命令或生产权限。

### 主控工具菜单与执行守卫不一致

`fixed-smoke-cross-2` 触发真实规划期限：约 186.5 秒停止，尚未派发。已返回的两次模型响应分别包含约 4,960 和 4,166 输出 Tokens；耗时主要在模型输出，不能将其解释为审批死锁。同时发现主控菜单展示 todo_write，执行守卫却禁止它，造成一次本可避免的失败调用。

菜单原来按 permission=read 判定，而执行端按安全规划控制/证据读取判定，两者对元数据工具的含义不同。现在 `planning-tools.ts` 提供统一 `coordinatorToolAllowed`，菜单和执行守卫共用；工作目录查询仍可用，改变目录仍被拒绝。独立会话恢复自己的待办工具。真实 Harness 首轮菜单与切回独立模式的回归已补充，规划/派发专项 34/34。

该修复消除内部规则矛盾，不能证明其是此次长推理的唯一原因，也不保证供应商以后不会超时。保留原规划时限、权限和失败记录，不延时刷绿。

另修正验收诊断的阶段归属：没有形成方案/派发任何任务就停止，应属于 planning；有方案未派发属于 dispatch；派发后的总任务阻塞才归 aggregation。补充项目、会话和运行 ID，新增正反边界回归。最终跨项目失败的原文件不改写，另存 `final-smoke-cross/reassessment.json`，结论仍是失败。

## 继续工作的顺序

1. 优先收敛主控规划输入和职责：宿主提供已经知道的团队、项目、能力与约束快照；将执行者的操作说明与主控决策上下文分离，保留 KIM 意图分析及同一准入/权限规则。模型应集中形成需求与任务契约，避免在派发前生成大量重复推理和无效工具调用。这需要设计角色上下文与规划接口，不能只添一句“请快一点”。
2. 准入/验收错误按具体字段、验收编号和缺失证据反馈；核验任务区分真正的用户交付与宿主审查，减少同一内容重复核验。继续保留独立审查和当前版本验证，不靠自动批准、关闭 Skills 或删除验收提高成功率。
3. 以这轮失败样本作为回归入口；新实现先通过相同预算的冒烟，再在同一冻结构建运行原 12 项矩阵，最后进行用户实际使用验收。当前不要按 R5 已通过推进发布。

## 性能与关闭边界

- 初轮同项目出现额外只读核验任务，再被宿主独立验证和审查，增加模型轮次。现有 purpose=assurance 会被拒绝，但模型将普通“读回并验证”表达为 user-check 时仍可能产生冗余；这是后续任务拆分精简的明确观察，不应通过删除独立审查求快。
- Tokens 按供应商已返回回执累计；缺失保留为未知，不填零。缓存折扣和实际账单未知，不将 Tokens 直接换算为费用。并行运行的各会话阶段用时之和也不等于整体墙钟时间。
- 验收使用隔离临时项目、真实已配置模型、正式 CLI/ConPTY，自动审批只允许检查过的测试文件操作和精确验证命令；不是对任意 Shell 自动授权。
- 自动化成功不代替用户人工实际使用确认。本轮不发布安装包、不推送 GitHub，不宣称全部外部 MCP、个人 Skills 或所有真实项目已经验收。
