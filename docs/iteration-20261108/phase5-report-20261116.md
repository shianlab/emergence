## 实现与代码结构

### 运行时与资源

`domains/data/runtime.ts` 负责应用目录、资源清单、依赖锁和活动环境定位；`domains/data/initialize.ts` 负责受控初始化；`probe.py` 检查解释器、准确依赖版本及真实导入。原 Data 服务仍是唯一计算入口，Code/KIM/主控派工执行链没有新增队列、执行器或状态副本。

新增 `emergence data-init --python "实际 Python 路径"`。CLI、诊断和 Data 服务读取同一个运行时描述；PowerShell 初始化脚本只调用 CLI，不保留第二份 pip 安装逻辑。当前数据环境限定 Windows x64 / Python 3.14，Python 主解释器仍需本机准备。

便携运行只读自身 `dist/data` 资源，检查清单、文件类型、路径和 SHA-256；不回退到开发目录。源码工程继续兼容既有 `.data-venv`。损坏的活动指针或资源会明确报错，不通过回退掩盖问题。

构建统一收录 worker、analytics、探测脚本、依赖锁和许可；发行脚本使用明确的 dist 文件清单，避免夹带源码映射和其他临时构建。五个依赖锁定为 duckdb 1.4.3、openpyxl 3.1.5、et-xmlfile 2.0.0、scipy 1.17.0、numpy 2.4.1，记录 wheel SHA-256，并保留 wheel 中的完整许可证与通知。

### 初始化与升级

每次重建在用户配置目录的新 UUID 路径中完成，检查通过后才原子切换活动指针。成功重建先备份旧指针，保留旧环境；失败只清理本次目录。复用既有文件租约和原子 JSON 存储，没有另建锁管理机制。

安装使用哈希锁和二进制 wheel，支持显式离线目录。缺包或哈希不符会失败，旧环境继续可用。测试发现 Windows 深层目录会导致 Python 初始化失败，环境路径改用依赖锁的 16 位摘要前缀，指针仍校验完整 64 位摘要；中文隔离目录中的初始化已通过。极长配置路径不作无限长度承诺。

安装器继续采用“验证 → 暂存完整版本 → 复核 → 切换入口”。补齐 Data 必需资源校验及失败暂存清理。配置 schema 没有为本阶段另加版本，沿用现有迁移、备份与未知版本拒绝策略。升级和卸载保留配置、凭据、历史、模板及应用目录外的数据环境。

使用步骤与目录策略见 [运行、数据环境与升级说明](runtime-and-upgrade.md)。
