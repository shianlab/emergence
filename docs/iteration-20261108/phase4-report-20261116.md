## 4A：编程闭环

### 根因与修复

原检查匹配只看命令文字。`npm run test` 在 `nested` 子项目执行成功时，可能被当成根项目同名脚本成功，即使根项目实现仍然错误。

已用真实 Harness 和 PowerShell 复现：根项目预期为 `not-run`，旧实现实际显示 `passed`，失败记录见 `code-cwd-before.log`。检查候选现在携带所属目录及本地命令，工具入口传入实际 `workdir`，执行回执保存命令与物理工作目录。只有对应目录/命令匹配才计入该检查，保留现有权限、执行循环和证据版本核对。

新增 `/code` 复用同一个 `CodeWorkflow`，显示当前项目、检查状态、实际目录、退出码、诊断及变更。不存在可识别检查时明确显示尚未验证。恢复预览复用原文件权限与版本保护，不直接写文件或取消用户原有修改。

### 验收

Code 专项 19/19，通过真实文件、修改保护、原有脏文件、检查口径变化、恢复与跨模块证据回归。新增子项目案例确认：子项目成功，根项目仍未运行，整体不虚报通过。

## 4B：数据闭环

原画像已有空值统计，但没有区分空白文本；交付报告没有集中展示输入质量。现在 `blankText` 独立统计，HTML/Markdown 报告增加中文“输入质量与范围”。HTML 转义，Markdown 质量文本以代码块呈现，避免把字段名当作可执行标记。

真实 CSV 案例含重复行、两个空白字符串和一个空值。断言完整保留三行、空白字符和源文件字节；仅显式清理参数才能修剪或去重。原始精确数字、标识符、口径版本、输入快照和可重算产物继续有效。

数据专项 14/14，包括真实 Python 计算、CSV/XLSX、只读 SQL、取消、输入边界、八类分析的黄金案例、报告与重算、原生独立审查。现有方法仍为清洗、指标、对账、留存、漏斗、贡献、二元 A/B 和日序列分析。

本阶段没有放大 8 MiB / 10000 行 / 128 列 / 100000 单元格限制，也没有新增远程数据库适配。报告明确完整扫描发生在既有预算内，不冒充大数据处理能力。

## 4C：使用体验与原生配置

`/doctor` 检查 Node、配置、依赖、项目路径、凭据存在性、Git 与独立 Python 依赖实际加载。探测使用固定参数、隐藏子进程、有超时及输出上限，不运行项目脚本、不解密密钥、不发模型请求。加密凭据库存在只表示“存在但绑定未验证”，不冒充每个模型已连通。

`/code` 和诊断结果经过统一脱敏。异步返回前检查窗口及项目是否仍然有效，避免把旧项目的结果放到已更换的会话中。中文帮助补齐目录切换和主控协作入口，保持原有命令优先顺序。首页/对话流程、黑白灰、原生聚合标识及主控角色视觉均保留。

原生 Windows Forms 通过 computer-use 在隔离配置中实际打开、编辑、展开高级参数、原值保存、查看分配页并关闭。大数值 `9007199254740991` / `2147483648` 没有截断；最终配置字节完全一致，关闭窗口后隐藏后端退出，附加模式可重新打开。

第一次原生脚本因自动化操作超过测试的 180 秒观察期限，被测试进程结束；保留 `model-native-first-timeout.log`。随后重新运行相同脚本，在期限内完成保存与真实关闭，全部断言通过，未放宽产品或测试超时。
