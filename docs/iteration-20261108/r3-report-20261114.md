# R3：统一审批响应与跨窗口可观测性

日期：2026-11-14。状态：R3 已实施并通过本地验收。R4 失败恢复和 R5 真实模型矩阵仍待推进，第三阶段整体尚未关闭。

## 本次解决的问题

原有 InteractionQueue 已有 ID/version 和取消能力，但工作台只观察每个窗口首项，原生审批日志 ID 与界面请求未建立统一关联；旧实测脚本依赖 task.status=waiting_user，再按窗口焦点输入 y。任务状态、焦点与请求更新不同步时，难以准确发现和回应全部待办。

本轮复用原队列及控制器门禁，集中发现所有实时请求，响应时核对完整身份。没有新增审批数据库、调度器、常驻远程控制接口或自动许可系统。

| 改动 | 结果 |
| --- | --- |
| WorkspaceInteractions | TUI、命令和测试共用列表/响应入口；列出所有队列项，显示是否轮到处理，不依赖任务状态推测 |
| 原生身份关联 | 原生 approval ID 直接作为该工具审批的交互 ID；保存 call、session/agent、turn、task/run、参数与权限指纹 |
| 过期与竞态处理 | 权限、运行、所属会话或参数变化后不能批准旧请求；无法核对的请求取消，不滞留为可批准项 |
| 终态回传 | 允许、拒绝、取消分别回传 allowed-once / rejected / cancelled；取消不再被测试当作尚未答复 |
| 相同操作重试 | 用户拒绝/取消后，同一轮相同代理、目录和完整参数的操作直接被拒绝，不反复弹审批；用户新一轮输入可重新发起 |
| 集中入口 | 点击主控栏“待确认”或 `/approvals` 查看所有窗口待办，选择后进入原窗口；选择本身不批准操作，原地 Enter/方向键/Esc 继续可用 |
| 精确命令入口 | `/approval <完整请求 ID> <版本> allow|deny|cancel` 按身份响应，焦点不改变目标；也支持无运行任务的宿主确认 |
| 原生元数据权限 | emergence_inspect 同时接受自身和 read 的限制；read ask 走原审批门禁，不再仅报受限；deny 继续拒绝 |
| 测试适配器 | 确定性测试直接调用相同进程内入口；真实矩阵脚本改为按原生日志发现请求、发送 ID 命令、验证对应终态；删除旧 Shell 变体白名单 |

## 架构与安全复核

交互数据类型放在 `core/domain/interaction.ts`；工作台投影/路由放在 `core/application/workspace-interactions.ts`；锁定 Harness 的日志关联放在 `core/adapters/approval-identity.ts`。app 保留交互队列、用户输入和原控制器执行权限检查，领域层没有引入文件或窗口 IO。

当前 Harness 的审批 waterfall 不直接传递 approval ID，因此适配器读取同一会话当前轮次已提交的 asked/decided 事件，以 tool + callId 唯一关联。存在歧义时拒绝推测，实际工具调用没有对应原生请求时返回 unavailable。宿主确认无原生工具调用，不伪造 native ID。

请求描述、选项和绑定被冻结；Harness 本身也冻结实际工具参数。答复再次核对实时权限、规范路径指纹和 task/run，关闭、接管、取消或轮次结束均不能把旧批准带到下一任务。队列仍保持窗口内顺序，不能越过首项批准后续操作。

新增 read 策略别名由宿主工具契约声明，模型或 MCP 注解不能自行申明。原生文件观察经正常工具审批后读取，读取前后检查权限版本与取消信号。没有为了通过测试关闭审批、放宽任意 Shell 或禁用外部 Skill。

旧 `respond(text)` 兼容入口仍由同一队列检查请求身份与有效期；TUI 和新测试不再依赖当前焦点猜测答复对象。已停用的主控栏“直接跳到第一个窗口”分支及测试 Shell 变体匹配逻辑已删除。

关键确定性场景使用真实 Harness、任务调度、审批服务和本地文件写入，模型为可控测试模型：

1. 主控加三个项目窗口，同时产生三个原生工具审批。隐藏 A 并切回主控后，允许 A、通过命令拒绝 B、取消 C；只有 A 真实写入，各原生决定 ID/outcome 正确。
2. 错误窗口、错误指纹、旧 ID/version 都不能答复。权限切换、接管、关闭和工作台重启后没有旧许可或写入。
3. 同一轮模型重复被拒绝的相同工具调用，只产生一次审批，后续重试没有副作用。
4. read ask 下的原生文件属性查询经真实审批成功，没有 Shell 调用；read deny 回归仍通过。
5. 实际参数和绑定不可变；注入 task.runId 变化后批准被拒绝，请求回传 cancelled。重复原生请求身份存在歧义时拒绝关联。
6. 无运行任务的宿主确认也进入集中列表；按 ID 命令确认成功，失效决策被取消。队列后续项可见，但不能越序响应。
