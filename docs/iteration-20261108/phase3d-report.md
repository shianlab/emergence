# 3D：时间、审批和失败恢复

日期：2026-11-12。基线：3C `05e62be`。本批完成；第三阶段仍需 3E 固定构建真实模型验收，不把本地回归当作真实模型通过。

## 实现

### 统一的阶段计时

- `domain/run-diagnostics.ts` 定义独立的 v1 诊断格式、中文阶段说明与期限；`application/run-diagnostics.ts` 负责单会话单轮的事件计时与看门狗；`storage/run-diagnostics-store.ts` 负责有界保存。控制器只接入既有模型流、工具执行、交互和会话状态事件，不承担第二套调度逻辑。
- 每轮按墙钟划分：宿主处理、模型首段响应等待、模型输出、工具执行、用户确认、可用窗口等待。重叠优先级为用户确认 → 资源等待 → 工具 → 模型 → 宿主。并发工具用集合记录，重叠时间只算一次。委派中的子工具归入所属会话的工具阶段，不把多个子进程耗时相加当作墙钟时间。
- 模型输出阶段由真实 reasoning/text/tool-call 增量信号触发。计时描述的是客户端观察到的阶段；供应商内部排队、推理计算、网络往返的进一步分解仍为未知。没有用 UI 动画推断模型进展。
- 排队、审批、暂停与执行任务总预算继续使用原 `RunClock`。主控匹配窗口期间以前被计入活跃规划，现在明确记为资源等待，使用已有 queueMs 与总预算。没有提高既有默认预算，也没有把重复规划当成完成进展。
- 取消时停止看门狗，但计时继续到实际会话空闲，覆盖工具清理的尾部时间。中断恢复只保留最后采样的时长，离线时间标为未知，不凭空补算为模型或工具耗时。

### 期限与恢复

| 阶段 | 本批使用的期限 |
| --- | --- |
| 模型首段响应累计等待 | 既有 `orchestration.budgets.planningMs`，默认 180 秒 |
| 模型输出累计时间 | `min(600 秒, totalMs)` |
| 工具累计墙钟执行时间 | `min(600 秒, totalMs)`，并发不重复累加 |
| 用户确认 | 既有 `approvalMs`，默认 1800 秒 |
| 可用窗口等待 | 既有 `queueMs`，默认 600 秒 |
| 本轮整体历时 | 既有 `totalMs`，默认 3600 秒 |

任务契约、主控规划、总任务已有的时长和步数门槛仍同时生效，以先达到的门槛为准。阶段时间在本轮内累计，连续输出、重复模型请求或短暂切换阶段不会清零续期。阶段计时不会授予新权限，也不绕过任务取消与恢复链。

阶段超时沿用 `TaskBudgetMonitor.expire` 统一停止任务，保留原预算原因码，附上停止时阶段；规划超时保留“主控规划”归属。审批拒绝、队列拥堵、供应商静默、工具阻塞可以分别诊断。运行记录没有被增加另一套可执行状态机。

供应商自动重试继续为 0，没有新增应用层网络自动重试，也不自动换供应商。写入后发生网络异常时保留实际副作用日志，不重写原文件；不确定状态依然先 `/recover inspect` 核对，再由原会话决定恢复。诊断数据只作为解释，不能证明“没有副作用”或作为重放授权。

### 用户入口与测试观察

- 既有任务详情面板增加“计时与处理”；`/tasks <任务ID>`、任务查询工具提供相同领域层说明，包括窗口、状态、阶段耗时、预算原因和处理入口。`/plan` 显示主控当前轮的阶段计时。`/recover inspect <任务ID>` 可读取保留的阶段诊断。
- 沿用黑白灰视觉和原交互，没有重做 TUI。显示“本轮结束”时明确不等于总任务验收成功；成功仍由 3C 的证据结算决定。
- 新的测试观察器使用独立的 `observation-deadline` 分类，记录观察上限、最后任务状态、阶段快照及停止是否确认。超出观察期限既不是生产预算失败，也不被当成成功。
- 已将 `master-followthrough-live.ts` 和 `runtime-live.ts` 接入该观察器。Windows 清理只使用测试自己持有的 PID 终止进程树，并等待退出；没有按进程名字扫描或杀死用户应用。诊断读取也有界，即使取不到快照，仍会停止测试拥有的执行。失败会保留“停止未确认”，不隐藏清理错误。

## 存储与兼容

新增文件位于用户数据目录 `core/run-diagnostics/<会话摘要>.json`，独立 `version: 1`，每会话最多保留 32 轮，单文件上限 128 KB，约每秒采样保存及结束时保存。只记录会话/任务标识、阶段、计数、时长和经过现有脱敏的错误摘要，不保存提示词、工具参数或密钥。

没有修改配置 v1、计划 v2、任务台账的持久化形状，不需要改写旧任务或迁移旧会话。旧任务没有诊断时明确显示未记录。未知版本和损坏诊断文件在绑定时保留原字节，当前使用内存计时并报告保存不可用；不会因可选诊断损坏而重放任务。历史任务、配置及台账仍是恢复与权限的权威来源。

回退时停止运行并保留完整用户数据备份。旧版本可以忽略新增诊断目录；不要只恢复部分任务台账。诊断只保留有限历史，不能代替完整会话与副作用日志。
