# R4：有边界的恢复与统一状态收敛

日期：2026-11-14。R4 已实施并通过本地验收，最终完整回归 340/340。R5 真实模型矩阵仍待推进，第三阶段整体尚未关闭。

## 根因与处理

这次发现并处理了三类不同的问题：生产 provider 配置把所有请求重试设为零；任务结算把历史工具错误直接当成未解决失败；代码检查只要后来同一检查成功，就可能把没有修复的偶发绿色当成恢复。已有任务调度、执行日志、审批和分阶段预算可以继续使用，无须增加第二套调度器。

| 层次 | 本轮规则 |
| --- | --- |
| 模型请求 | 复用 dsh-base 已挂载的 dsh-llm-retry，在原轮次、原模型、原历史上最多额外请求两次。仅 SERVER、RATE_LIMIT、TRANSPORT、STREAM_CLOSED；初始退避 500 ms，上限 2 秒，10% 抖动。pi-ai 的底层 HTTP 自动重试继续关闭，避免次数相乘。 |
| 永久错误与期限 | 鉴权、余额、参数错误不列入重试；TIMEOUT 也不自动重试。重试等待计入模型等待时长，沿用原任务执行、排队、审批和整体期限；取消可中断退避。 |
| 只读失败 | 在同一运行内，同一只读查询后续两次尝试中的有效回执可以解决失败。原生 schema 确认参数无效、且实际返回 INVALID_ARGS 时，允许纠正参数；新调用仍经过正常权限检查。不会通过解析错误文案猜测可重试性。 |
| 证据提交错误 | emergence_assess / emergence_report 的错误只在同一轮该工具后来真实成功提交后标记解决，保存旧 call ID 与替代 call ID。 |
| 真实测试失败 | Shell 非零退出不会被后续零退出直接覆盖。代码修复路径要求源码版本改变、有本次实际变更、测试口径不变，并取得当前版本检查；同一源码版本跑到绿色仍不通过。原有独立核验发现缺陷后进入有界修复的机制保留。 |
| 未知副作用 | 写入、Shell、MCP 和未知工具不获得只读恢复资格；已返回写入后的模型断线只重试下一次模型请求，不重放写入。进程中断或执行结果不明继续要求核对日志、产物和显式恢复决定。 |
| 用户决定 | 派发任务及其绑定子代理的工具审批被拒绝/取消后停止所属任务；原队列负责取消待办，不能换参数自动继续。独立会话仍保留 R3 的同轮相同操作阻断。 |
| 收敛 | 主控、验收、经验证明使用统一的“未解决失败”判定；结算和验收重新核对替代证据。错误历史保存于 result.failures 和原生日志，errors 仅作为旧界面的未解决错误投影。 |

安全的只读纠正发生在当前运行内。已经结束的失败审查不会因轮询自动创建新的业务任务；无法证明安全、超过次数或期限时明确阻塞并保留原因，不靠重复跑到绿色关闭总任务。

## 代码边界与巡检

- `core/domain/task-failure.ts` 定义失败与解决关系和兼容判定；`core/application/task-failures.ts` 负责实际事件/回执关联及证据重验。领域层不引入 IO，任务写入仍经 TaskLifecycle。
- `tool-evidence.ts` 只接收宿主观察的校验结果。INVALID_ARGS 分类同时要求本机工具 schema 校验失败及原生错误码；模型返回值不能自行声明“安全失败”。
- `task-execution.ts` 删除旧的批量忽略 metadata 错误分支，统一调用失败归并；不新增全任务重试循环。旧记录没有新字段时仍按原错误保守处理。
- `model-config-runtime.ts` 是 CLI 启动与配置热更新共同的 provider 配置来源；锁定并显式声明原已存在的 retry 依赖，未升级其他包。
- `run-diagnostics.ts` 将退避归入模型等待，不新增计时器或延长期限。TUI 仅补充重试状态文案，保留既定视觉与模型配置插件。
- 复核中发现只读校验不必要地查询外部工具定义，已将该访问限定在已知只读工具。回归测试中的并发证据额度仍在执行前预留。
- 保留 R1–R3 和此前未提交改动；没有提交、推送、安装包发布或额外后台服务。锁文件保持原 CRLF 格式，实际仅新增一条直接依赖。

## 故障验收

| 场景 | 观察结果 |
| --- | --- |
| 正式 CLI + 本地 HTTP 500 / 429 | 各两次 HTTP 请求、一次持久化重试，随后成功结束；没有底层重试叠加。 |
| 正式 CLI + SSE 不完整工具参数后断流 | 适配器分类为 TRANSPORT，一次请求重试后成功；零工具执行，项目目录无写入。 |
| 正式 CLI + 401 | 一次请求、零重试，明确失败退出。 |
| 持续 SERVER / 永久错误 | SERVER 最多三次请求；鉴权、TIMEOUT 一次后终结，工作窗口不会永久 busy。 |
| 退避中取消 / 期限到达 | 旧等待中断，不再启动后续请求；累计模型等待不能因重试刷新。 |
| 已写入后连接中断 | 后续模型请求重试两次，实际写入与副作用记录仍各一次。 |
| 只读错误、原生参数校验错误 | 新的真实回执解决对应失败；旧失败、参数指纹和替代关系仍可检查，重启后保留。 |
| 无关读取 / 过期读取 / 超额尝试 | 均不能清除原失败；改变文件后替代证据失效。 |
| 真正测试失败 | 原有真实验证进程仍触发有界修复；未修复而重跑到绿色的新增负例不通过。 |
| 写后进程死亡 / 重启 | 既有实际子进程故障测试通过：副作用未知状态保留，不自动重放。 |
| 多窗口审批 | 三窗口允许、拒绝、取消各归其主；过期身份、模式变化、接管和关闭仍被阻断。原生 TUI 键鼠、窄屏、草稿保留及 Windows ConPTY 回归通过。 |
