# R2：统一项目、子任务与验证契约

日期：2026-11-14。状态：R2 已实施并通过本地验收。R3–R5 尚未实施，不能据此宣称跨项目协作已完成真实模型整体验收。

## 修复结果

之前同一个“两个项目都通过”的总验收会进入两个子任务及各自的审查上下文，导致重复跨目录核对、额外命令和审批。本轮将总目标与局部贡献分开持久化：总目标保存原始验收及贡献映射，子任务只收到本项目的局部验收，独立 verifier/reviewer 继承相同边界。主控汇总时检查贡献是否齐全，再继续现有独立证据验收。

| 改动 | 行为与约束 |
| --- | --- |
| ProjectRef | 项目身份由真实规范目录生成，处理 Windows 大小写及 junction，支持无 Git 文件夹；错误 projectId、越界 scope、变化后的路径绑定被拒绝 |
| LocalCriteria / GoalContract | 原始全局验收不丢失；跨项目共享要求必须说明各项目的局部贡献，缺失引用、直接复制共享全局要求、删除贡献均被拒绝 |
| 显式集成任务 | user-check 单独声明 readProjects 和依赖；只能引用登记项目，既有读取权限继续生效；调度冲突计算包含被读取项目，防止与写入同一项目的任务并发 |
| VerificationSpec | 精确绑定工具、命令、cwd、局部验收编号、输入与配置；宿主在准入时记录配置 SHA256，执行前后核对版本；修改验证脚本、缺失输入或其他项目回执不能证明通过 |
| emergence_inspect | 使用宿主只读文件/目录观察，返回哈希、字节数、UTF-8 有效性、BOM、末尾换行与目录直接成员；不需要临时编写 Shell |
| 全局闭环 | 缺少总目标契约或任何贡献任务时不能汇总成功；保留独立审查、任务版本、原生回执及最终产物检查 |

## 代码结构与安全边界

- 领域结构集中于 `core/domain/project-contract.ts`；真实路径规则放在 `core/application/project-contract.ts`，不在领域层做文件系统 IO。
- 规格准备由 `verification.ts` 负责，复用原 `tools/execute` 和 `tool-evidence.ts` 执行及记录；没有新增调度器、命令执行器、权限白名单或独立事实库。
- 绑定与基线写入原协作状态；准入事务失败同时回滚任务和总目标。基线采集跨越异步 IO 后再次核对窗口、权限及批次，幂等比较不把宿主基线当作模型请求的新参数。
- 独立模式没有自动开启协作；原 KIM、外部 Skill、模型路由、TUI 和原生模型配置界面保持既有工作方式。
- 项目限制约束结构化文件工具、会话目录及验证命令。普通 Shell 继续走既有审批，**不是操作系统文件沙箱**，无法仅凭 cwd 限制其内部任意路径访问。范围声明不授予额外权限。
- 原生属性查询遵守原有 read 禁止规则；read 需要额外审批时不会静默放行，当前返回受限。审批交互统一属于 R3。
- VerificationSpec 为可选字段：有明确规格时强制匹配；无规格任务保留既有通用核验。历史记录可读，不伪造基线或将旧失败改成成功。
- 结构化贡献映射和零退出码不等于证明业务语义正确，仍保留独立 reviewer。文件属性观察上限 8 MiB，目录直接成员上限 1000，超过预算明确失败。

## 验收证据

最终使用项目锁定 Node 运行全部 `tests/*.test.ts`：**323/323 通过，失败、取消、跳过均为 0**。日志：`artifacts/r2-full-final-pass.log`。

关键场景使用真实 Harness、调度器、权限、持久化及文件操作，模型端为可控测试模型：

1. 两个项目、两种模型路由并行派发，各自修改文件；各自的 verifier/reviewer 保持原项目与独立会话；执行真实本地 Node 检查进程，两个交付及四个审查完成后主控汇总。
2. 第三个集成步骤等待两个交付通过后读取各自文件；继承声明的跨项目读取范围，并完成独立只读核验。遗漏该集成贡献时总目标结算拒绝。
3. 普通无 Git 目录、大小写/路径别名、junction 改指向、错误项目 ID、越界 scope、未登记读取项目、执行会话目录变化均覆盖。
4. 实际命令退出、脚本基线、输入版本、同项目规格身份均核对；脚本篡改、过期产物、其他项目回执、缺失输入、任意命令变体无法替代约定检查。
5. 原生文件属性/目录查询在独立会话可用，真实读取 UTF-8 BOM/CRLF；显式 read deny 阻止查询，不创建协作任务。
6. R1 历史重放仍保持原结果。新增宿主规格回执兼容测试：绑定无效时不得降级使用旧读取回执掩盖失败，历史 JSON 不改写。

完整回归同时覆盖原有同项目任务、取消、恢复、审批拒绝、权限交集、审查独立性、Code/Data、模型配置、Skills/MCP 等既有用例；这不等同于重新实测每个外部服务。
