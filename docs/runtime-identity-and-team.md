# Emergence Harness：运行身份、鼠标编排与自动治理接通

日期：2026-10-30。本次依据用户的两张实际使用截图修复产品行为，不以之前的模拟测试结果代替使用效果。

## 身份与事实来源

此前启动 profile 只增加了 Emergence 的 persona，没有关闭上游 system-prompt 插件默认的 `harness:identity`，同时模型没有收到完整的应用运行事实。因此它可能回答“DeepSeek Harness”，甚至无法说明界面已显示的模型 ID。

现在启动配置显式关闭上游身份开场，由 `runtime-identity.ts` 从执行中的 Agent 读取实时模型选择、项目、核心开关、当前任务路线、窗口模式和可派工窗口，并通过 Harness 的必需运行上下文提供给模型。应用为 **Emergence**，运行层为 **Emergence Harness**；模型 ID 来自实际请求配置，不假装知道供应商内部权重版本。

事实每轮重算，也适用于恢复会话和模型切换。底层执行依赖、Meta_Kim 来源和第三方署名继续如实保留，没有删除许可或改写旧聊天历史。用户目录中的旧 `meta-theory` Skill 不是内置核心的启用依据，也不修改其他应用的 Skill 安装。

## 鼠标设置主窗口

打开至少两个窗口后：

1. 在想作为主窗口的窗格边框/标题或顶部会话标签上右键。
2. 点击“设为主窗口”。如果终端占用了右键，可直接点击窗格右上角的 `[窗口]`。
3. 主窗口显示克制的红色边框及“主控”角色，其余现有窗口加入执行团队；之后新开的窗口也自动加入。无色终端保留文字角色。
4. 把任务发给主窗口，它可以通过现有编排器选择空闲执行窗口。每个窗口的项目、模型、权限及接管状态继续生效，设置主窗口不等于提升权限。
5. 在主窗口菜单选择“取消主窗口”，恢复各窗口独立工作。还有待处理任务时先完成或取消任务；切换主窗口也受该约束。

菜单不发送聊天、不回答审批、不清空草稿。角色配置和自动加入设置持久化；关闭主窗口沿用已有逻辑回到独立模式。用户暂停派工后新增窗口不会自动解除暂停。通过旧命令建立的明确 worker 列表仍保留原语义，只有鼠标设置团队启用自动加入。

## 自动治理的实际执行

以前虽有入口分流与复杂计划门禁，但模型缺少完整自我能力事实、轻量任务缺少目标分析门槛、界面也没有持续显示治理状态。新增以下连接：

- 每条普通请求在 Harness 接纳时自动分流，状态显示“已自动分流 · 直接回答/轻量执行/正在规划”。纯问答不强行建任务图。
- 新增原生 `emergence_analyze`，由模型记录目标、路线理由及发现的隐藏复杂度。该工具属于内置核心，无需读取或安装 Skill；一次请求只记录一次目标分析，后续调整走计划修订。
- 轻量实施任务可以先读取来源，但在目标分析前，宿主拒绝写入、命令等副作用。分析可把轻量/直接路线升级为复杂规划，不能把既有复杂任务降级绕过计划。
- 复杂任务提交的结构化计划本身形成目标分析记录；继续经过能力、证据、项目/会话绑定与权限检查，再进入既有持久调度器。
- 主窗口收到普通工作请求、有可派工窗口时自动走规划路线。执行窗口按已接收的契约工作，不再次启动竞争的主控规划。
- 状态显示“目标已分析”“方案已检查”“已进入任务编排”等实际事实；`/plan` 可查看目标分析及理由。核心关闭时如实显示关闭，不用动画假装治理运行。

轻量任务没有额外创建九个代理。路线初筛是程序规则，语义目标由模型分析；复杂任务仍受模型质量、实际能力及预算限制。并非声称上游全部源码或可选外部服务已移植。

## 验证

`artifacts/runtime-team/inspection.json`：12/12 组检查、115/115 项单元与 Harness 集成测试通过，包括类型检查、本机构建、原生鼠标菜单/红框/草稿/重启、既有任务与规划/恢复/记忆交互，以及 Windows ConPTY 输入和审批。源码摘要在同轮检查及结束后复核均无变化。

新增集成覆盖实时身份、自然语言隐含复杂度升级、计划门禁，以及“不输入派工命令，设置主窗口后发送普通任务 → 原生计划工具 → 执行窗口实际写文件”。任务未结束时禁止改换主窗口。

`artifacts/runtime-team/live.json`：使用实际已配置的 `api.deepseek.com / deepseek-flash`，在临时项目中检查：

- 应用准确回答 Emergence Harness 和当前模型 ID，并知道内置核心自动参与。
- 输入普通的“修改 notes.txt 并读回”，没有点名 KIM、Skill 或工具，实际调用 `emergence_analyze`，完成真实编辑和读回。
- 首次实网检查中模型曾先尝试 edit；宿主门禁拒绝了该次调用，随后模型完成目标分析再编辑成功。这证明执行约束实际生效，也说明不能宣称模型每次都会在第一次尝试就遵循流程。后续已强化模型上下文中的前置说明。

实网检查没有验证大样本复杂项目质量；多窗口自动派工用受控模型配合真实 Harness/文件验证。凭据不进入报告，第三方外部 MCP 未配置状态保持不变。

复现：`npm run inspect:runtime`。`npm run test:runtime-live` 是独立的显式实网测试，会产生少量 API 用量。重新打开 `emergence` 即加载本次构建；已有进程不会热替换代码。
