## 本轮修复

完整链路测试发现：单窗口规划产生的本地任务在进入修复时，丢失了 `local` 执行标记，被误当成必须投递给 worker 的任务，报“目标不是可派发的执行窗口”。修复创建新尝试时沿用原任务的本地执行方式，并继续继承原权限、角色权限、范围及修复预算。

新增回归实际走通：模型提交规划 → 真实文件执行 → 独立读取发现错误 → 一次有界修复 → 新会话审查 → 实际子进程验证 → 基于当前证据验收 → 经验候选 → 原生用户批准 → 工作台关闭恢复 → 后续请求召回。候选不能提前召回，恢复不自动重放任务。

该闭环使用确定性本地模型夹具；文件与子进程、Harness、调度、审批、证据和存储均实际运行。它证明链路契约，不证明真实模型能稳定自行完成任意复杂任务。

## 性能与负担

轻量请求采用同一构建的 `core off` / `observe` 对照，各 8 个新会话，交替顺序、无网络、GC 后计量。两组均只调用模型一次，输入均为 3094 字符；中位延迟分别为 6.10 ms 和 8.72 ms，差约 2.62 ms。样本较少，包含运行时抖动；具体延迟与堆变化见 `artifacts/core-phase6/benchmark.json`。

没有可复现的整合前构建基线，因此不宣称相对旧版本的提速或成功率提升；此对照也不能估算真实模型的 token、账单或网络延迟。完整复杂链路是一个受控场景，成功 1/1、修复 1 次、模型请求 22 次，其中包含失败审查、独立复查验证及记忆操作；不是统计意义上的任务成功率。

稳定性采用已有五分钟测试：预载 200 轮历史，四窗口持续流式输出，同时进行中文输入、切换、缩放和创建/关闭；另有 16 会话、192 轮的短时并发测试。五分钟结果已固定到 `artifacts/core-phase6/stability.json`，不据此声称全天运行无泄漏。

- 实际持续 300.4 秒，完成 1092 轮、1252 次输入采样，4 次创建/关闭循环。
- 输入响应 P95 为 101.0 ms，满足测试的 150 ms 阈值；最大 313.8 ms，长尾延迟仍需在实际试用中关注。
- 峰值 RSS 493.6 MiB，低于 1 GiB 阈值；GC 后残留堆增量低于 80 MiB，Agent 注册表清空，无执行错误。

## 本机试用与回退

现有全局 `emergence` 命令链接本工作目录，已构建到本地 `dist`。关闭旧进程后，在自己的项目目录运行：

```powershell
emergence
```

建议按此顺序试用：

1. 输入 `/`，用方向键选择命令，查看 `/help`、`/keys`。`/permission plan` 可先只读讨论；需要执行时按实际需要切换权限模式。
2. 布置一个范围明确、包含验收条件的小任务，用 `/plan` 查看计划，确认实际项目、窗口与工具；需要时用 `/plan run` 提交。
3. 在 `/tasks` 查看任务、产物与状态；用 `/audit` 区分执行结束、审查、验证和用户验收。待确认时按原生选项操作，Esc 可返回。
4. 用 `/memory` 查看候选，`/memory show <ID>` 看具体内容，批准后在同项目新会话验证复用；`/memory forget <ID>` 撤回后续召回。
5. 用 F2/F3 增加窗口，F6 关闭窗口；重新启动核对历史。中断任务先 `/recover inspect <任务ID>` 核对实际结果，再决定后续操作。

`/core off` 可关闭核心规划/观察路径，`/core observe` 可重新开启；设置会保存并同步当前工作台的窗口。这是运行开关，不撤销已经完成的文件修改，也不删除任务和记忆。审批模式继续有效。记忆撤回不会自动擦除既有对话、导出或备份中的历史内容。需要完全隔离的实验可通过 `--home <新目录>` 使用独立配置，并单独配置模型凭据。

实网验收只操作临时测试项目，不迁移用户凭据，不制作安装包或发布 GitHub。
