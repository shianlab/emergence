# Code / Data 增强第一阶段交付报告

日期：2026-10-30。范围：统一能力契约、证据清单、兼容迁移与初始基线。第二至第六阶段未实施。

## 已接入运行链的能力

新增 `src/core/domain/tool-contract.ts`，以宿主代码中的可信目录声明内置工具的输入、输出、读写性质、资源范围、副作用、取消支持、预算和证据种类。权限、KIM 规划、文件任务分配、副作用日志及观察器共用此描述。工具名仍是查找键，但不再在各层重复维护相互独立的读写名单，也不会依据模型参数或 MCP 的 `readOnlyHint` 授权。

未知工具保留可扩展性：需要原有权限审批，进入任务分析流程，网络/数据库影响标记为未知；不能借 `emergence_` 前缀免除回执，也不能声明自己只读便取得文件并行资格。宿主源码及进程内扩展仍是可信代码边界，这不是操作系统沙箱。

新增 `run-manifest.ts` 和 `tool-evidence.ts`，接在现有活动任务的工具执行中间件上。真正调用工具后，由宿主记录任务、运行、会话、调用编号、参数和结果摘要、脚本命令摘要、文件输入/输出版本、环境、状态及校验结果。实际文件内容复用已有 SHA-256 观察；不信任工具自己返回的 manifest。命令正文、环境变量值和数据行不写入这个清单。

清单依附原有任务回执，保存到现有持久化体系；没有另建调度器或任务数据库。治理控制工具不产生可用于自我验收的证据。查询仅记录查询快照，任意命令和未知外部工具不会被冒充为已追踪全部输入输出。

## 本轮修复与边界

- 统一成功判定：异常、超时、非零退出码为失败；取消不能成功；后台启动和缺失退出码表示未完成。子代理命令失败仍向所属任务传播，并保留具体退出码。
- 文件读取前后版本变化、文件缺失、文件无法可靠观察，不能生成成功读取证明；写工具声称完成但没有可核对的文件产物，也不能作为成功产物证明。
- 独立审查提交时及后续查询时重新检查引用文件；变化后的输入和输出使旧证明失效。
- 活动任务最多 128 条证据，先预留正在执行的名额，避免并发越过上限；耗尽后在实际执行前阻止继续消耗。取消和异常也释放预留。
- 保留 plan / ask / edit / auto、路径范围、显式拒绝、子任务继承和独立审批的原有边界。
- 旧任务回执可以没有 manifest，不补造过去的运行环境或文件版本。新清单版本固定为 1，不支持的版本拒绝解析。兼容方向是新程序读取旧数据，不承诺旧二进制理解新字段；回退前应保留数据副本。
- 本次顺带修正共享控制器中一个可空对象的类型收窄，保留另一界面的 Tokens 展示改动，未重做视觉或模型配置插件。

没有独立验证的逐工具时间/输出上限用 `null` 表示，不能解读为已具备资源沙箱。文件观察仍受现有 8 MiB 上限约束，超过上限标记未知；大数据流式摘要留到第四阶段。本阶段新增清单覆盖活动调度任务，不宣称所有独立闲聊、任意子进程或外部服务都具备完整数据血缘。

## 真实模型初始样本

使用本机当前默认配置 `glm-coding / glm-5.3-flash`，OpenAI-compatible 通道，Windows、Node v26.13.0。每次响应上限 2048 tokens，每任务 120 秒，隔离的合成项目，无用户业务文件写入。两项均使用构建后的 CLI，未安装参考仓库或额外 Skill。仅授予各自完整匹配的检查命令。

| 样本 | 实际结果 | 耗时 | 工具调用 | 供应商累计 tokens |
|---|---|---:|---:|---:|
| JavaScript 数组边界修复 | 自动分析、读取、修改、执行检查；宿主额外核对 n=0/1/3/17，全部正确 | 44.1 秒 | 5 | 63,155 |
| CSV 收入统计 | 读取真实 CSV、生成计算脚本并执行；总收入 170.5，east=120.5、west=50，有效订单 4、重复/退款/金额缺失各 1 | 117.0 秒 | 7 | 96,344 |

已从持久会话中复核工具真实输出和进程 `exit code: 0`，不是依据助手回复中的“通过”。Tokens 是多次响应的累计供应商回执，包含缓存读取，不等于单次上下文长度或计费金额；费用未测量。明细见 [真实样本](../artifacts/code-data-phase1/live-baseline.json) 和 [回执复核](../artifacts/code-data-phase1/live-baseline-review.json)。

这两个样本证明当前通用工具链能完成小型代码修复和计算任务，不证明整体 Code/Data 能力已经增强，也不代表稳定成功率。它们不是方案中 C1–X2 全套验收题的完成结果。

版本限制也已记录：首次样本运行与最终加固构建并行，原 runner 在报告时才记二进制 hash，因此该 hash 不能作为每个样本实际二进制版本的证明。保留这些初始样本，不用于“同版本性能提升”比较。已将后续 runner 改为每任务执行前后记录 hash、拒绝构建中途变化，并直接核验持久工具/进程回执；新 runner 通过类型检查，未重复消耗 API 重跑这两项。最终产品回归单独记录其稳定源码版本。

可复用入口为 `tests/code-data-baseline-live.ts --live`；不会混入自动单元测试。`review_live_baseline.py` 可离线复核已保存样本，无新增模型请求。

## 查缺补漏与下一阶段

1. 当前能调用文件、进程、Skills、MCP，也已有 KIM 规划和真实派工；缺的是领域理解、领域执行和领域验收的专门实现，而不是再叠一个 Agent 主循环。
2. 小任务已显示较多累计上下文消耗，CSV 样本还进行了额外目录探索。第二阶段应改善项目画像、相关上下文选择和按需能力信息，保留 KIM 的必要治理约束。
3. 尚未测量大型仓库、LSP、Excel/Parquet、本地 SQL、统计推断、大文件、复杂多窗口任务的成功率与性能；不能把本阶段的 182 项回归当作这些能力的质量评分。
4. 后续 native Code/Data 工具必须补宿主契约，继续经过原权限、资源分配、执行回执及独立验收；领域工具不自行授予权限或另建任务事实源。

下一阶段为**第二阶段：编程项目理解与上下文增强**，随后第三阶段完成编程修改与验证，再连续进入第四、第五阶段的数据增强，最后第六阶段统一联调验收。
