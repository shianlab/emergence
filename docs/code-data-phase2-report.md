# Code / Data 增强第二阶段交付报告

日期：2026-10-30。范围：原生项目理解、代码定位、上下文选择及恢复；第三阶段的修改、测试修复闭环尚未开始。

## 已接入产品

新增三个默认可发现的原生工具，使用现有 Harness 工具协议、权限、KIM 规划和回执，不需要安装或点名 Skill：

| 工具 | 能做什么 |
|---|---|
| `emergence_code_project` | 观察语言、package/workspace 配置、包管理与锁文件、入口候选、测试配置、项目指引文件、Git 现有改动；列出脚本但不执行 |
| `emergence_code_locate` | 按符号或问题关键词查找定义、引用、导入候选，返回真实路径、行列、文件 hash 和定位方法 |
| `emergence_code_context` | 根据定位结果选取实现、引用方、关联导入和测试片段，保留来源与版本，按预算返回 |

例如直接问“定位这个项目中 computeRevenue 的实现、调用方和相关测试”，模型可以主动使用上述工具。真实模型试用未在用户提示中写工具名称，实际选择了原生定位与上下文工具。

实现按职责分在 `src/domains/code/`：`project.ts` 负责扫描与画像，`languages.ts` 负责语言适配，`service.ts` 负责结果选择与输出预算，`harness.ts` 负责接入现有会话、权限及恢复。没有新建 Agent 主循环、任务数据库或独立派工器。

## 语言理解的实际边界

**TS / JS：** 按需使用 TypeScript 5.9.3 Language Service，在本次有界只读源码快照内解析定义和语义引用，关联静态导入及测试调用。已有 TypeScript 依赖从开发依赖提升为运行依赖，锁定版本未变；没有额外下载安装另一套 Agent。

不会执行被分析项目的 JS 配置、构建脚本或 TypeScript 插件。只读取本地 `baseUrl` / `paths` 等惰性解析字段；不加载完整依赖库类型、继承配置或 project references。服务返回的语义结果限定于实际读取的源码，不能当成完整项目类型检查。语言服务接口依据 [TypeScript 官方说明](https://github.com/microsoft/TypeScript/wiki/Using-the-Language-Service-API)。

**Python：** 按需启动宿主解释器，以固定代码调用 `ast.parse`，源码作为 stdin 数据输入，不导入或执行项目模块。提供函数/类定义、名称引用及本地导入候选，明确标记 `python-ast-name-hint`。这不是 Python LSP 的跨模块类型语义；没有把“解释器已启动”包装成完整语义能力。隔离启动参数和 AST 用法依据 [Python 启动参数](https://docs.python.org/3/using/cmdline.html) 与 [AST 文档](https://docs.python.org/3/library/ast.html)。

语言服务缺失、解析失败或超预算时返回文本定位与明确警告；不会把文本命中标成语义引用。Windows App Execution Alias 的 Python 路径已实际适配。

## 上下文、版本与恢复

- 每次定位重新建立有界源码快照，并以文件内容 hash 标识版本；文件修改后不会继续使用旧符号索引。
- 上下文只选相关片段，保留原文件、行号、版本与选取理由；源码中的文字是项目数据，不授予执行权限。
- 原生源码观察通过宿主执行上下文传递到第一阶段的证据清单，不能从模型返回的 JSON 伪造。解决了 Harness 规范化/复制工具返回值后，普通对象引用无法携带证明的问题。
- 回执覆盖返回结果引用的文件；超过可追踪来源数量时同步裁剪结果，并标记截断，避免给出无法重新核对的额外位置。
- 读取期间文件变化会让宿主回执失败，并将工具结果标为错误；后续独立审查仍重新核对版本。
- 恢复指针来自持久会话中的真实原生工具事件。启动时索引历史，之后只消费新增事件，保留有界指针，不因固定历史条数而过期。实际 Harness 压缩后以及重启后均测试了恢复。
- 每次恢复核对当前项目、权限及文件版本；换项目不带入另一项目的片段，变化/缺失文件标记失效。普通无关问答不会重新加载上次代码片段。
- 当前目标、约束、未决问题继续由现有 KIM 计划与压缩机制保存；本模块补充定位来源，不另存一份竞争性的任务状态或擅自批准长期记忆。

## 资源与安全检查

| 边界 | 实际实现 |
|---|---|
| 扫描根 | 当前工作目录的物理路径；Git 根单独报告，不自动扫描整个父项目 |
| 读取预算 | 最多 256 个文本文件、单文件 256 KiB、总文本 4 MiB；候选清单最多 6000 项 |
| 输出预算 | 工具 JSON ≤24000 字节、定位最多 40 条、追踪来源最多 24 个、上下文片段最多 8 个；超限标记截断 |
| 服务预算 | 宿主辅助进程有取消、输出和时间限制；Python AST 最多 40 个文件；TS 引用查询最多 8 个候选定义 |
| 项目边界 | 跳过依赖、构建物、缓存、默认隐藏目录及链接；路径越界拒绝；不自动读取 `.env` |
| 忽略规则 | 优先 rg；支持非 Git 项目 `.gitignore`。缺失时降级 Git 文件清单；两者均不可用时，有限遍历保守跳过含 `.gitignore` 的子树 |
| 权限 | 原有 Plan/Ask/Edit/Auto 仍生效；逐文件继承 `read` 和本工具的限制；检索过程中权限或工作目录变化则拒绝交付结果 |
| 执行边界 | 宿主解析器只分析数据；Git 仅读状态且关闭可选锁及 fsmonitor；不执行项目脚本、不 reset/stash、不载入项目插件 |

TS 解析采用进程内语言服务，取消是协作式检查，不宣称具有任意同步计算的硬实时抢占或操作系统沙箱。Git 状态是当次观测；源码回执仅绑定列明文件，项目画像不等于全仓库/依赖库验证。

## 测试与发现的问题

新增 7 项专项测试，覆盖：项目画像与真实 dirty Git 状态；TS/JS 定义与语义引用、测试关联；Python AST 不执行模块及文本降级；中文/CRLF、边界、忽略、预算、取消；真实 Harness JSON 协议；真实压缩恢复；Plan 模式下调用、持久证据、重启恢复、文件变化及跨项目隔离。

最终 **189/189 项测试、8/8 组巡检通过**，检查期间源码未变化，依赖声明与锁文件一致。全量回归包含第一阶段及既有权限、调度、记忆、会话、模型配置测试；另有严格类型检查、本机构建、原生文件/PowerShell/Skill/MCP/模型协议端到端、故障恢复、权限交互、规划反馈与终端协作。最终结果见 [inspection.json](../artifacts/code-data-phase2/inspection.json) 和同目录日志。

真实试用最初暴露出可选字段为 `undefined`，导致严格工具协议拒收的问题。已将返回值规范化为无损 JSON，并新增真实 Harness 回归覆盖项目画像和 Python 结果；不是仅修改模型提示或放宽协议。

修复后，当前默认 `glm-coding / glm-5.3-flash` 在 Plan 模式完成两轮真实调用：第一轮自然语言定位 TS/Python 实现、调用方和测试；第二轮宿主改名后重新定位新函数及核对旧调用。整个样本约 106.6 秒，8 次工具调用，累计供应商 tokens 98,357（含缓存，费用未测量），无缺失 usage 回执。未修改业务项目或运行样本项目脚本。

这是一个真实模型的功能样本，不代表稳定成功率或性能改善。详见 [live.json](../artifacts/code-data-phase2/live.json)。该样本在最终恢复索引、相对导入细节收尾前运行，收尾变更由最终本地回归覆盖；未为此再次消耗 API。旧 runner 只记录 CLI hash，已补 Harness bundle hash 检查供后续运行使用，并保留本次运行后的 bundle 记录与限制说明。
