# Emergence 1.03 发行核验

本版在 1.02 安装发布流程上继续完成修正。1.02 源码和本机检查曾全部通过，但只改变文档及稳定清单后的重复 CI 捕获了两个时序问题，因此没有启用 1.02 稳定通道。

## 根因与职责

1. Windows 替换文件期间，另一读者偶尔获得瞬时 ENOENT。修正位于唯一 JSON 文件机制 `safe-json-file.ts`，最多重试三次（5/10/20 毫秒），每次重新校验。持续失败、非法类型、坏 JSON、大小超限仍向调用方报告错误。
2. TaskEngine 取消任务先保存记录、后停止会话；保存较慢时模型可能进入下一步。TaskExecution 在模型步入口检查已经生效的取消状态，包括本任务及其原生子代理。任务状态仍由现有生命周期管理，不另设取消状态机。

审批回归使用受控的持久化等待门复现竞态，不靠固定睡眠掩盖问题：旧实现稳定触发额外模型请求，修正后在保存完成前就停止。文件回归覆盖并发写入/读取、占用重试，以及真正缺失、非法 JSON、大小超限的错误保留。

## 发行规则

修正后的源码通过 45 项完整巡检，其中包括 381 项单元/集成以及真实 Harness、Skills、MCP、模型配置、恢复、TUI 和终端测试；检查期间源码没有变化。安装专项 41 项通过。两个并发场景连续 10 轮、共 110 项检查通过。安全扫描未发现已知保存凭据泄漏，依赖审计没有已知漏洞。

完整巡检后仅将发行 README 标题改为不绑定版本号的产品名称，避免后续修订保留旧标题。最终包与巡检构建逐文件比较，允许差异仅为 README 和打包时间；程序载荷保持一致。

已公开的 1.02 资产和签名不覆盖、不重签为另一份同号程序。修正版本为 1.03 / 1.0.3，使用新的 ZIP、摘要、签名发行序号与标签。只有最终包、源码检查及匿名安装验证通过，才合并稳定清单并设为默认最新发行。

1.02 候选的外部验收由用户反馈提供，未附机器日志；本次修正不宣称另做了外部电脑测试。机器证据保存在忽略目录 `artifacts/publish-v1.0.3/`，原始 1.02 核验保留在 `artifacts/publish-v1.0.2/`。
