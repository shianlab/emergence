# E1–E5 后端与能力层复核

日期：2026-10-30。结论：本次后端验收通过，已修复发现的问题。用户在巡检中明确要求 UI 留给另一个页面继续设计，因此最新 TUI 不纳入本次最终通过结论。E1–E5 已交付，不等于任意模型、任意外部服务和所有 UI 版本都已验收。

## 已修复

1. **修复任务可能扩大角色权限。** 原实现重新读取角色配置；原任务失败后若把研究角色改成自动执行，重试可能取得更宽权限。现在保存独立角色快照，修复继承原角色限制和主控派发时的权限快照，同时仍接受当前主控与执行窗口限制。新增测试先复现错误，再验证研究角色始终无法执行被禁止工具。
2. **旧任务可能进入替换后的会话。** 执行窗口新建会话、换项目或换模型后，旧任务原先仍可发起修复。现在校验主控和执行窗口的会话 ID、目录、模型与任务绑定，不一致时要求按新范围显式派发。新增测试验证替换会话后拒绝修复。
3. **修复交接遗漏原有上下文。** 原实现只传修复反馈和结果摘要。现在优先保留原契约上下文，再附加修复说明与结果，仍受已有上下文长度限制。
4. **外部诊断可能包含未注册凭据。** 原脱敏主要依靠环境中的已知密钥和 Bearer 字段。现在额外移除 URL 用户名/密码、常见敏感查询参数和 Basic 认证信息，保留普通查询参数以便排障。新增回归覆盖未注册的外部凭据。

在用户调整范围前，早期界面回归还发现关闭快捷键提示消失，已恢复动态关闭键提示；后续另一个页面继续更新 UI，该结果不代表最新 UI 完整验收。

## UI 留待单独验收

巡检中曾跑通部分首页、Markdown、输入、审批与历史交互测试，但另一个页面持续修改共享界面，使整体巡检中途出现版本变化与类型错误。用户随后明确将 UI 排除；因此保留早期失败记录，不把 `npm run inspect` 的旧失败报告改写为成功。
