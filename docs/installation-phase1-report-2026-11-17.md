# 安装改进第一阶段报告

日期：2026-11-17。范围：安装可靠性、部署速度和安装后启动检查。本阶段不发布 GitHub 新版，不升级真实用户安装，不增加版本提醒；后续继续按四阶段方案推进。

## 已完成的修改

### 下载与引导

- 将单次整包下载改为有上限的流式下载、重试与退避；提供下载进度和中文阶段说明。下载仍使用系统 .NET 能力，不要求用户额外安装 curl、Node 或 npm。
- 按发行物 SHA-256 保存完整包和部分包。断线保留部分数据；重试支持 Range，不支持续传的服务器则安全重下。已有完整包校验成功后直接复用。
- 校验失败的内容不能进入安装。覆盖过大响应、截断、超时、错误状态码及不允许的跨域/协议重定向；不会为“成功安装”关闭 TLS 或完整性验证。
- 下载缓存和应用目录分开管理，加入排他锁、所有权检查、7 天过期和空间限制；诊断日志保留最近 20 份。不删除用户项目、配置、密钥和会话。
- 解压前检查重复/危险路径、Windows 名称别名、链接、展开体积和可用磁盘空间。失败提示指出阶段及日志位置。

### 部署与启动

- 按已验证清单限并发复制文件，替代逐目录复制；验证目标文件的长度和哈希。失败等待已有 IO 收尾，避免复制尚未结束就开始清理。
- 不再为每次安装遍历所有历史版本；检查本次实际访问的受管路径。完整卸载仍保留整个目标树的链接检查。
- 加入安装健康探测：实际 CLI 版本、OpenTUI/SQLite 原生依赖、Harness 启动和内置工具、Windows Forms 依赖。使用独立临时配置及无外部模型请求的 `/tools`，不使用用户真实密钥。
- 只有文件和启动探测都通过，才启用候选版本。文件哈希正确但无法启动的包也会被拒绝。
- 修正重复安装覆盖回退记录的问题。将 PATH 准备放在当前版本指针切换之前，减少“入口准备失败但已切到新版”的情况；完整崩溃事务仍在第二阶段完成。
- 发现同版本安装损坏时给出关闭程序、使用发行包卸载程序再安装的路径，明确保留用户配置；自动原位修复属于第二阶段。
- 诊断写入失败只发出提醒，不把已经成功启用的应用误报为失败。

职责入口见[安装与发行维护边界](structure/installation-maintenance.md)。安装管理仍只有一套入口，未向 Agent 循环添加第二套安装/更新逻辑。

完整引导测试仅在测试包装层将官方 URL 映射到本地 HTTP 发行物，生产脚本没有测试地址开关。公开网络下载另行使用真实 GitHub 地址验证。

同一台机器、相同文件集，交换测试顺序各测两次，复制完成后完整校验：

| 部署方式 | 第一次 | 第二次 |
| --- | ---: | ---: |
| 原来的递归复制 | 30.17 秒 | 34.14 秒 |
| 新的限并发清单复制 | 9.72 秒 | 11.67 秒 |

这说明本机**文件复制阶段耗时约减少 67%**，不是完整联网安装提速 67%。目标校验另需约 2.8–3.8 秒；新加的启动检查也有耗时，不能省略后只宣传速度。

## 包体核查决定

候选包含约 647 MiB 展开文件、31,101 个清单项和 613 个依赖组件。此次没有通过删除功能来减包体。

- TypeScript 在 `domains/code/languages.ts` 中动态加载，是编程能力的运行依赖，不能当作纯开发缓存删除。
- 上游 dsh 安装依赖包含 Office、语音及检查界面等组件；profile、插件和扩展存在动态加载。没有完整证明其所有受支持入口都不使用之前，保留这些组件。
- 本阶段实际优化的是断线重试成本、缓存复用和文件部署 IO；没有宣称 ZIP 显著变小。后续若需要轻量版，应单独明确可选能力及按需安装契约，不能偷偷裁掉原有能力。

## 证据与剩余边界

证据目录：`artifacts/install-phase1-20261117/`。

- `check-final.log`、`tests.log`、`installation-tests.log`：代码与自动测试结果。
- `release-validation.json`：安装专项结果及对应隔离候选。
- `bootstrap-validation.json`：最终完整引导、缓存复用与卸载结果。
- `public-download/result.json`：真实公开下载记录。
- `copy-benchmark.json`、`footprint.json`：速度与文件体积数据。
- `completion.json`：最终源码指纹和证据归属。

这些测试运行在开发机的隔离目录、限制 PATH 和临时配置中，不等于一台全新 Windows 实机验收。外部电脑实际体验安排在第四阶段。用户已确认拿不到历史报错与修复命令；该个案仍为原因未确认，不把本次测试当作已复现并修复的证据。

测速产生的四份完整临时副本约 2.5 GiB。删除操作被自动审批拒绝（仅返回 `blocked by policy`，未给出详细原因），因此保留，没有通过其他方式绕过。测速数据和日志不受影响。

本轮没有改变 GitHub 下载入口、发布标签和真实本机安装。版本发现、更新提示、自动修复、完整回退事务、正在使用的旧版本保护与清理，仍由第二至第四阶段完成。
