# 第六阶段：先在本机反复调试

当前工作版本：0.1.0，本地调试状态。按用户最新要求，先保证电脑上的运行和调试体验，安装包和 GitHub 发布后置。

## 直接使用

当前电脑的 `emergence` 命令已经连接到 `M:\涌现TUI\emergence` 工程，不需要重新安装：

```powershell
cd M:\你的项目
emergence
```

退出旧实例后重新启动，可使用最新已构建代码。配置、Windows 加密凭据、会话和模板继续保留在涌现配置目录。

修改代码后，在工程目录构建并启动：

```powershell
cd M:\涌现TUI\emergence
npm run dev -- "M:\你的项目"
```

`dev` 每次先构建，再启动应用。运行中的任务不会因为文件保存而自动重启；需要验证改动时，结束当前实例并重新运行此命令。

## 本地检查

```powershell
emergence --version
emergence doctor --json
npm test
npm run inspect:local
npm run inspect:audit
```

`doctor` 只读检查本机运行时、目录、配置和依赖；不发起模型请求、不解密或输出密钥。可以用 `--output diagnostic.json` 保存脱敏结果，已有同名文件会拒绝覆盖。发现加密凭据文件时仅报告其存在，不假称当前模型凭据已验证。

`inspect:local` 包括前五阶段回归、第六阶段本机功能、三种终端宿主和故障恢复检查。`inspect:audit` 额外覆盖依赖审计、参考包完整性、短时 16 窗口检查和已配置凭据的明文扫描。默认流程不执行安装、打包或发布，也不重复收费模型调用。

持续运行检查可单独执行：

```powershell
npm run test:stability
```

默认运行 5 分钟，检查四个窗格持续输出时的中文/emoji 输入、窗口创建与关闭、内存和输入响应。最近一次结果仍新于相关核心源码及依赖锁时，普通巡检复用该结果；相关代码有改动就重新运行。测试使用真实 Harness、JSONL 和 OpenTUI，模型输出由本地测试适配器控制。

## 这轮本机改进

- 长会话界面使用最近 200 条显示记录的增量缓存，完整历史与导出仍保留。
- 解决流式刷新覆盖刚输入或刚清空的草稿，异步失败只向原会话恢复输入。
- 启动尚未结束就退出时，等待初始化结束并完成资源清理，避免晚到会话或界面。
- 异常退出后可安全清理标记为自身所有、超过保护期且进程已结束的临时 profile；未知文件和仍运行的进程保留。
- `emergence config migrate` 先备份原始配置，再补齐兼容的默认设置；损坏或未知版本不会被覆盖。
- 增加断流、429、500、启动器被结束后的恢复回归，确认已发生的写文件操作不会被自动重放。

## 调试节奏

先在实际项目里使用独立窗口和协作模式，遇到问题后记录：操作步骤、当前窗口/项目/模型、预期与实际结果、能否重复出现。修复时补对应回归，再运行本地巡检。

当前自动验证覆盖 Windows 11 x64 下的 Windows PowerShell 5.1、PowerShell 7 和 cmd/ConPTY。真实输入法候选框、字体和长时间实际项目工作仍需要本机试用验证。另一供应商的实网验证也需要对应凭据；本轮保留 DeepSeek 的既有实网证据，并补做一次小型真实启动检查。

安装、升级、卸载和发行包实验保留在工程中，不进入默认调试流程。等本机试用与反复调试确认稳定后，再按用户要求继续安装包和 GitHub。
