# 模型配置工具

2026-10-30 最终界面约束：Windows 原生控件和本地 `.exe`，不采用网页、WebView 或浏览器外壳；白底紧凑双页签和既有模型配置/分配范围保持。

用户已授权先规划后实施（2026-10-30）。这是涌现随附、可独立打开的可视化模块。

1. 当用户从命令行、首页、对话命令或明确的自然语言请求打开配置时，系统应打开本机可视化配置窗口，不调用模型。
2. 当用户编辑模型时，系统应校验配置 ID、协议、端点、模型名和凭据引用，保留其他项目设置；密钥仅用现有 Windows DPAPI 存储，不回传已保存值。
3. 当用户点击连接测试时，系统应使用该配置的协议发送小型请求，给出耗时与成功/鉴权/限流/协议/超时结果，不仅检查密钥是否存在。测试可能产生少量 API 用量。
4. 当工作台已打开时，系统应显示所有可见及后台窗口、稳定 ID、角色、当前模型和状态；用户可为空闲且无协作关联的窗口独立应用模型并保留会话历史。
5. 当用户保存窗口默认模型时，系统应区分单窗口、主窗口、副窗口及第 2–16 窗口，下一次新建时使用；恢复已有布局保留原模型，显式 --model 和模板优先。
6. 当窗口忙碌、配置过期、模型仍被引用或服务断开时，系统应明确拒绝相关操作，不静默覆盖、不强行中断任务。
7. 按用户后续修订，配置工具应为白色/浅灰的轻量小窗，顶部提供“模型库 / 分配”双页签；无侧栏或大标题，模型按需编辑、默认规则折叠，支持键盘、可见焦点与窄窗口。TUI 的深色外观保持不变。

本轮不扩展 Agent 编排，不引入云端账户、不代理日常模型流量、不修改其他应用配置。
